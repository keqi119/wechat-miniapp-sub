# 人工信用核验及订阅权益实施补充

用户已确认人工核验与押金边界，并批准信用说明v1、隐私政策v2及申请须知v2。确认记录与文本哈希见 `docs/legal/credit-approval-manifest.json`。既有直接施工授权继续有效。本计划先完成信用档位到最终方案的贯通；权益阶段在月界、退订、换车细节明确后继续，不用文案替代结算。

## 第一阶段：人工核验与押金

- 专门的申请级同意，关联当前已发布的 `credit-verification` 文案版本、申请、客户和实际点击时间。一般登录同意不能替代，默认不勾选，可暂不授权并转人工联系；提供撤回入口。无真实客户点击时不得由后台伪造。
- 运营只录入档位 GE750 / B700_749 / B650_699 / LT650 / UNVERIFIABLE，并确认已核对客户主动出示页面；核验人、时间取会话与服务端。不接收精确分数、截图、自由证据字段。核验记录追加保存，不覆盖历史。
- ADMIN/OPERATIONS可核验本人有权处理的申请；客户仅能读取本申请结果与本人授权。审计保留必要归属/动作，不复制敏感页面或输入。
- 发布最终方案须有当前有效、同意未撤回的核验。月费整数分乘以0/1/2计算押金；后端拒绝任意押金覆盖及不匹配的核验版本。LT650/UNVERIFIABLE保持人工处理，禁止正式方案。已有月费5,199对应0/519,900/1,039,800分。
- 核验变更或撤回使未确认旧方案不能被客户继续确认；生成新方案固定核验ID、规则版本与计算结果进商业哈希和快照。已确认合同保留当时事实，后续撤回不改历史订单金额。
- API先确定并发、幂等、同意撤回/新核验/最终确认竞态契约，然后两前端接通。生产暂未有正式申请或订单，无需伪造历史核验迁移。

建议契约（由API实现人员细化并同步）：

| 方法 | 路径 | 含义 |
| --- | --- | --- |
| GET | /customer/applications/:id/credit-review | 本申请的授权/核验safe状态及当前说明 |
| POST | /customer/applications/:id/credit-consent | 客户明确接受当前说明，绑定本申请 |
| POST | /customer/applications/:id/credit-consent/withdraw | 撤回本申请后续核验授权 |
| POST | /admin/applications/:id/credit-verifications | 录入已人工核实档位、幂等键与声明 |

先测试缺少/过期/其他申请授权、撤回和并发、0/1/2档押金、低分/不可核验阻断、前端无法指定审核人/时间以及客户越权。使用独立测试库，本地不触发真实信用核验。完成后复核法律文本哈希并发布新版本，重新展示隐私变化及申请授权；尚未授权的客户不能被后台标记已核验。

## 第二阶段：已确认商业规则与实际台账

- 基础每个订阅月1,500公里，从起租日起按月计算，月底余额清零；先用基础，再用加购包。
- 加购包1,000公里800元、2,000公里1,500元、3,000公里2,000元，可叠加；当前订阅期内余额逐月结转。支付可信到账后才发放，重复回调不能重复增加。
- 退订时加购里程及加购换车权益失效；用户明确规定不退还未使用加购费用，须在加购前显著展示并固定同意版本，异常履约或争议由人工处理，不自动绕过合同争议程序。
- 免费换车每12个月周期1次，加购800元/次可叠加，当前订阅期内有效、退订失效。
- 每个订阅月截止时客户提交仪表里程和照片，人工审核；缺报或证据不足先补证并暂停该期里程费用结算。不能凭跨月总读数自行平均分摊。
- 现有累计读数及文字权益不足以结算，需新增按月使用台账、里程包产品/购买快照/到账发放/消费流水、车辆分段分配及换车申请/交接、退订结算。并发审核、付款和退订按订单序列化；保留不可覆盖台账与渠道原单号。

已进一步确认：订阅费按月先付，因此中途退订当月仍享完整1,500公里；实际交车晚于约定起租日时从实际交车日开始，双方先确认延期后的费用和合同日期；加购可抵扣本订阅月已产生但尚未结算的超里程，已结算月份不追溯；免费换车每12个月重置1次，未用不结转；换车运营逐次报价，客户先确认差价、交接费用及补充协议，原合同剩余期限不变。正式套餐继续未启用，待结构化结算与协议流程落实后再启售。
