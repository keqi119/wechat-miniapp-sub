# 后台统一流程实施计划

**目标：** 订单详情可理解、可办理，其他长流程使用一致提示并保留业务门槛和现有 UI。

- [x] 后端：新增后台专用只读订单流程投影与真实资金/交付/归还待办；按需提供显式交付条件重核命令；严格本单查询和岗位权限。先写本单典型阻断、异常/退款及 GET 无写入测试。
- [x] 共享及其他模块：通用流程展示、合同/保单/产品/合作商/现场任务/结算摘要；操作回执区分写入与读回。保留既有版本规则。
- [x] 订单前端：常驻阶段和当前待办，本单内合同、资金、任务、交接及结算办理；保留切换节点输入、滚动、409 数据，防止跨订单请求/操作串单。
- [x] 主控整合：关联入口返回上下文、App 集成、接口文档与操作基线；检查已有申请页与全局台账兼容。
- [x] 验证：独立测试库领域/HTTP/权限测试，前端测试及类型构建，浏览器真实渲染验证桌面/窄屏/返回位置/当前测试订单阻断。
- [x] 审查及发布：冻结明确源码差异，保留全部业务数据、支付/实名配置和自动账单任务，安全发布后只读核验线上流程与本单。

分工：后台 agent 只写 orders 流程与明确列出的只读抽取/工作区文件；订单 UI agent 只写 order-workspace 与新增 order-process/order-*-panel 文件；公共模块 agent 只写 process-guide、domain-ui 及合同/保单/产品/合作商/用量模块。主控负责 App、导航、发布、基线文档与跨组件整合。API 测试使用项目独立库与锁，不并发运行不同测试进程。
