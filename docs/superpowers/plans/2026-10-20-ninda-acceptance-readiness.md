# 宁达人工验收准备与接口启用实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 按用户连续授权发布宁达两份协议、录入三台来源可追溯的车辆及价格、启用支付实名签署接口，并生成备案用透明印章图片。

**Architecture:** 继续使用宁达独立 API、数据库和域名；通过现有管理员 API 写入法律文档和车辆，不直接改业务数据库。签署主体从显式生产配置读取，保留企业印章、双人批准及逐单签署校验。

**Tech Stack:** NestJS、Prisma、PostgreSQL、Node.js 运维脚本、Docker Compose、微信小程序、内置 imagegen。

**Spec:** `2026-10-16-miniapp-independent-platform-design.md`；当前会话用户关于宁达迁移、两份协议发布、三台车辆、接口启用与印章 PNG 的最新指令覆盖旧主体配置。

## Global Constraints

- 仅新项目和宁达服务器可写；旧公开法律/车辆接口及库存表只读。
- 金额整数分；不复制历史客户、合同、付款、会话和授权。
- 当前仅用户协议与隐私政策获准发布，其他法律模板不自动批准。
- 接口开关授权不扩展为代理发起真实支付、实名或签章。
- 图片为备案素材，不将生成视作法大大已备案或企业用印授权。
- 主控管理配置、构建和部署；并行人员只写分配文件；保留既有改动，不提交/推送。

## Review Focus

- 最新直营协议与旧车主版本容易混淆：以旧公开接口正文 SHA256 为准。
- 旧公司硬编码会出现在新合同和印章校验：测试宁达公司在生成文本和签章归属检查中一致。
- 原表采购里程、当前里程和出租状态不得混用，不把缺失字段变成已核实事实。
- API 重建必须保留数据库、会话、实名和备份密钥以及当前付款证书文件。
- 接口已启用与实际业务可完成分别核对，缺合同/印章/渠道权限时保留明确错误。
