# 保险发布与交付门禁调整计划

Spec: `docs/superpowers/specs/2026-11-12-insurance-delivery-gate-design.md`

1. 保存当前源文件快照与哈希，在项目内隔离候选目录实施；已有工作不提交、不覆盖。
2. RED：发布无保险可通过；交付要求两险和真实原件；覆盖时点、批改/退保、替代单、普通/换车最终门禁与现有 UI。
3. GREEN：抽出交付保险核查，移除发布保险项，接普通及换车交付；后台响应严格检查由七项改六项。更新接口约定。
4. 验证：针对性 API、后台 UI、TypeScript 构建；一次独立最终审阅。以测试证明最终提交重新读取，不依赖预览缓存。
5. 核对生产不可变基线，生成最小镜像/静态差异；加密备份并验证可恢复后发布。确认现有电子签自动执行配置和核心业务数据不变。
6. 线上只读确认发布条件和健康状态，记录版本及验证证据，不代执行业务。

Review focus: 单/批/总开关发布路径是否全部解耦；普通及换车实际交付是否全部覆盖；原件/类型/时间/批改的真实证据；缺项定位；实际提交不可沿用预览结果；保留已启用自动签与其他并行改动。
