# 独立加购实施计划

1. 核对当前usage、swap、billing、退款与客户页面来源；保留旧规则和真实历史。
2. API先测独立SKU版本/范围/三档价格，建立后台维护与客户资格目录，再接严格报价下单。
3. 月包V2绑定原计费月，完善当期/历史待结算投影、结算扣额、期末失效及晚到账核账退款；旧V1保持原规则。
4. 目标换车SKU接入既有赠送/付费预占消费账本，在实际目标报价、预占和完成均校验车型范围。
5. 后台新增平级紧凑商品模块，复用会话未决命令与版本冲突保护；小程序用车页同页选购、既有账单支付，保持三级内与当前视觉。
6. 独立审查、完整构建、新数据库迁移与关键事务/并发核验。刷新副本中未修改的先行后台基线，精确合并增量，不覆盖其他工作。
7. 提交测试后台与小程序体验版供人工验收；商品价格与发布由运营如实登记，不造生产报价或真实交易。

人工验收增量：统一灰色框内筛选提示和紧凑同排按钮；产品工作台全宽左右布局并验证较矮桌面/窄屏无组件重叠；补齐车辆全库组合筛选，以及 BaaS 的 VIN/车牌、出租方、品牌、车型、承租人输入/选择筛选和电池规格列。上述界面与只读查询纳入同批冻结、构建与验收发布。
