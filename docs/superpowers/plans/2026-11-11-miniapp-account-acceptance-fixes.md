# 1.3.3 登录、资料与车辆申请修复

用户 2026-11-11 报告问题，并进一步确认：短信登录双勾选后可用；协议勾选合为一行，两种登录方式切换；沿用已有有效合作协议，新客户合同仍电子签。此明确选择覆盖此前要求所有历史纸质合作先补签电子协议的规则，仅针对既有有效合作来源，不开放新的纸质签署写入。

## 设计与范围

- 小程序资料校验接受已上线的 SIGNING_REQUIRED，与后端和资料页一致。姓名、手机号、脱敏身份证及三个已分类证件从本人真实资料读取；新上传保留其他证件、版本与幂等保护。
- 登录页默认手机号快捷登录，顶部两种方式切换，同一时刻只显示一种登录操作。协议用一项明确勾选同时同意当前两份文档，两个正文入口独立可读；仍分别传递两份文档 id/version，切换方式不替用户同意，文档/会话变化撤销同意。
- 既有 ACTIVE 历史合作来源沿用原有文件证据、当前关联、完整租期及运营限制校验。不得伪造电子签/补齐缺失事实；新订单和客户合同继续 ELECTRONIC，纸质写入口仍关闭。
- 只读核验指定账号确认后台资料完整；不代用户发送真实短信、签署、付款或创建订单。业务测试使用受保护的本地隔离库。
- 保留共享工作区的其他任务，目标文件施工前快照在 `.runtime/miniapp-account-fix-20261111/before/`。API 与小程序发布以实际电子签生产版及已上传 1.3.3 冻结源为基线，只带本次增量。
