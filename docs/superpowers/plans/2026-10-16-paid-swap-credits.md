# 付费换车次数实施计划

继续执行已批准独立平台方案、已确认换车商业规则及 `apps/api/phase-b-design.md` 的 B3 切片。无需新增商业规则确认；本计划不批准任何真实付款、退款或签署，也不把模板批准当作客户购买同意。

## 范围和数据边界

- 当前订阅内 800 元/次，整数 80000 分；每笔购买一份一次权益，可分别多次购买叠加。不增加未获确认的折扣、自动扣费或跨订单转移。
- 客户必须核对订单、次数、金额，单独阅读并接受已发布 `vehicle-change` 文案版本及 hash，显著展示退订失效且未用费用不退、例外情形仍按实际依法处理。通用登录同意不能代替购买同意。
- 新建专门购买快照和账本，沿用 B2 每个 PAID credit 唯一来源 payment 的结构。只有已核验的真实支付结果才 GRANT，一笔支付最多发放一次；客户端成功回调不是到账依据。
- 免费优先，实际完成日决定周期；付费次数预占、消费、退款冻结、退订失效与 B2 同一订单锁顺序一致。新周期免费次数可用时释放原 paid 预占，不能重复扣次。
- 仅完整未使用且未预占的一次购买支持既有双人复核的全额例外退款；已消费、部分退款或预占中的退款明确阻断。未知渠道退款保持冻结，不能人工标记已到账或重新消费。
- 退款申请在渠道执行前被拒绝时，财务可显式恢复原已付权益，不能另发次数：须原款仍成功、原权益未用未预占、订阅有效，且相关退款全部被拒绝、从未批准或调用渠道。同订单锁、最新退款版本、理由和幂等审计共同守门；曾执行渠道或结果未知时只能继续核验原退款，不允许恢复。
- 退订/期限结束停止购买与支付；未支付单安全关闭，未知支付先查询原单。真实晚到支付必须保留到账事实，按冻结/例外退款处理，不给已结束订单可消费次数，不能丢失真实收入记录。
- 所有开发和验证只使用新独立本地测试库及合成供应商，不操作生产、不连接旧库、不读取真实身份证或发短信。

## 顺序与分工

1. API 先完成 B2 与原生入口合并及回归，再发布 `apps/api/b3-contract.md`：购买/账户安全投影、购买状态和退款状态、幂等/版本字段、角色权限及失败恢复。迁移新增 018，不能改写已存在 017。
2. API 先补关键失败用例，再接购买账单、可信支付、次数发放、退款冻结/结算与退订竞态；固定来源文件不改。既有月费、押金及里程包逻辑保持其真实业务约束。
3. 后台在 B2 恢复表单提交封存后，按稳定 DTO 增加购买来源、收款/退款/冻结/消费状态及审核入口；不能通过通用权益编辑手工加次数。
4. 小程序在 B2 与原生入口合并封存后，增加当前订阅购买/同意/主动微信支付/服务端查询/恢复操作；显示订单和明确 800 元/次，不将验收 0.01 元金额混入正式产品。
5. 独立交叉审阅和本地真实 HTTP 接线验证完成后，主控冻结包、审计密钥、备份并部署独立新系统，发布已批准换车模板。正式用户支付与签署仍在具体记录内容核对后由本人操作。

## 必须验证的业务风险

- 越权、未授权/过期文案、客户端改价、重复点击/不同请求复用幂等键、重复付款回调、错误金额/商户/订单不能发次数。
- 支付在途与退订/期满、到账与退款冻结、退款与换车预占/消费并发；未知结果必须查询原单，不另起重复收费。
- 免费优先及跨周年、重复完成仅扣一次、取消未完成申请释放预占、原合同剩余期限及里程余额不受购买影响。
- 例外退款需要完整未使用来源、独立审批、真实渠道结果；失败/超时不能自动恢复可消费余额，重放不能重复扣减或退费。
- 两前端对接实际安全投影，错误状态可读、主动重查保留原业务记录；生产开关关闭时明确显示不可用。

验证记录必须区分本地合成测试、真实生产健康检查和本人实际渠道验收，不能互相替代。
