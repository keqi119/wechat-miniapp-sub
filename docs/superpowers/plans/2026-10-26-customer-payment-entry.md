# 待支付订单与账单入口修复 Implementation Plan

> For agentic workers: 使用 subagent-driven-development；已授权直接施工，主控发布并整合证据，不提交或推送。

**Goal:** 没有已发布账单时准确提示等待发布；发布首期后客户可以沿现有入口本人支付。

**Architecture:** 保留原有账单草稿、发布、本人微信支付流程。只读订单与首页根据本订单本客户的已发布未付账单派生引导，不新增交易接口或客户端权限。

**Tech Stack:** NestJS / Prisma / TypeScript，现有微信原生 1.0.7。

**Spec:** 2026-10-16-miniapp-independent-platform-design.md 已批准的付款和交付流程；本节记录此次缺陷的具体修复设计。

## 证据与选择

2026-10-26 17:18 生产只读核验：本单 AWAITING_PAYMENT，12期账单全部 DRAFT，首期金额1分，押金0分，付款流水0。首页与订单却提示查看已发布账单。1.0.7冻结代码编译验证：合法PENDING账单已有查看入口和立即支付按钮，无需新包。

选择在API修正引导并按用户明确确认发布首期。自动发布全部账单会扩大收费范围；在客户端对草稿显示付款按钮不符合已批准的发布门禁，均不采用。保持聚合canPay=false，付款仍由原账单详情与服务端校验。

用户已明确确认：按现有2027-10-25付款日，仅发布本单首期0.01元，其余11期保留草稿。此授权不包含实际付款、改合同日期或交付确认。

## Global Constraints

仅本项目写入、仅宁达新生产环境上线；旧库不连接。密钥不输出。金额整数分、客户归属/RBAC/幂等/回调校验保留。没有生产迁移、代签或代付。保留既有脏工作区，用精确已上线基线冻结两个API源文件。

## Review Focus

- 无PENDING时不能引导到不存在的已发布账单；只有已付账单时不提示再次付款。
- 其他客户或其他订单的账单不能影响本单引导。
- DRAFT/REVIEWED/VOID不对客户公开，不开放交易动作。
- 已发布账单沿原详情支付；不按未来付款日误隐藏。
- 合同归档与资金到账、实际交付仍是独立门禁。
