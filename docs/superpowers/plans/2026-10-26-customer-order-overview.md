# 客户订单详情与首页进度实施计划

> 执行方式：沿用用户已授权的直接施工，采用分工实施、先测试后修复及独立审查；不创建真实签署、支付或交接。

**目标：** 客户看到本单真实车辆、已确认费用与条款、合同/账单/交接进度，首页下一步与当前订单阶段一致，编号只出现一次。

**设计：** 在现有原生小程序记录页中增加订单专用展示，保留其他记录类型。API按会话归属聚合只读订单视图；价格与期限使用确认快照及已生效变更条款，不读实时套餐价格替代。主摘要常显，合同、账单和交接分别列出，较长交易条件按需展开。时间按北京时间展示。首页优先显示最近未结束订单，才回退未成立申请。

**技术与范围：** 现有 NestJS/Prisma、原生 JS/WXML/WXSS，无数据库迁移。修改API客户订单聚合和home；小程序记录页及必要适配。1.0.4保留，下一包从该冻结包派生，仅带本轮审查文件。

## 边界

- 客户归属必须在服务端查询条件内，关联合同/账单/交接也限定同一订单与客户；不输出内部账户、供应商原始响应、证书或信用资料。
- 金额整数分；月租、押金、期限、起止日、月里程、超里程、能源、权益、实际出租方、交易条件按快照展示。已生效变更使用effectiveTerms，并区分原始与当前约定；不能用原车型充当换车后当前车辆。
- 草稿账单不可呈现为可支付账单。DRAFT合同只说明准备中，已有文件/签署状态按真实记录展示，不仅凭订单待签约就给“立即签署”。只读入口沿用有归属检查的合同/账单详情和文件接口。
- 不重复订单ID、状态；不显示ISO UTC原串。待签约、待支付、待交付、使用中、结算中、完成/取消各自保持一致。
- API先上线兼容字段，再上传小程序；不改旧系统、生产订单或当前管理员并行业务操作。
