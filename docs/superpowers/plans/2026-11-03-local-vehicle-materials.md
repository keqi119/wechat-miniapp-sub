# 本地车辆资料匹配 Implementation Plan

> 主控执行受控API写入；并行人员只写各自私有分析目录。用户既有授权允许生成计划后直接施工。

**Goal:** 将来源文件准确关联到现有车辆，按原件补足可靠事实，列清冲突和未处理资料。

**Architecture:** 只读来源抽取、VIN/车牌双重核对、不可变差异计划、现有领域API执行与回读。

**Tech Stack:** Node.js、Python/pypdf、现有NestJS后台HTTP接口。

**Spec:** `docs/superpowers/specs/2026-11-03-local-vehicle-materials-design.md`。

## 约束与审阅重点

仅当前宁达系统；原文件只读；全部私有数据在.runtime；整数分；当前RBAC/版本/幂等/审计保留。证件合同不得发布为车辆图片。目录归属与文件VIN冲突、保单/发票混淆、历史资料覆盖当前值、重复文件/重复保单、上传成功但关联失败均须显式处理。

## 任务

- [x] 读取83辆车及资产、83条BaaS、9份保单和牌照快照；80个目录车牌唯一匹配。
- [x] source目录：清单、PDF/DOCX逐页抽取、VIN证据、不可读文件统计。
- [x] matching目录：先以合成案例测试同VIN/异VIN/重复文件/已有值冲突，再输出逐文件关联及逐字段差异。
- [x] insurance目录：提取来源明确的保单字段，区分保单/批单/发票/非车险，以现有保单去重，不伪造审批。
- [x] 主控审阅可执行变更及缺项，必要的文件事实由原页视觉复核；写入器先测试版本冲突、同键重放、失败停止和读回不符。
- [x] 使用既有后台领域API执行已确认事实，逐步日志与回读，最终核对车辆/状态及无意外业务变更。
- [x] 用户确认统一附件归档，设计补充独立车辆私密原件关系及API。
- [x] API任务：新增vehicle-documents服务/控制器与合成行为测试，扩展共享隐私映射阻断；根负责Schema、迁移、注册、隔离库约束测试。
- [x] UI任务：新增逐车原件列表/上传/下载入口及组件测试，复用当前后台视觉和会话客户端。
- [x] 冻结实际改动与当前生产基线差异，独立审阅、构建、受控兼容发布；不包含无关改动或小程序发布。
- [x] 原件上传计划逐文件SHA、目标车辆ID/VIN、原相对路径、类别；源树只读，经正常API上传，逐车在固定服务器只读核对实际存储字节SHA、大小及数据库绑定；另真实下载五类格式样本并核验隐私边界。
- [x] 交付匹配、补录、冲突及遗漏统计。
