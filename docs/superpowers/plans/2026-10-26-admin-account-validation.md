# 后台账号密码校验反馈修复 Implementation Plan

> For agentic workers: 使用 subagent-driven-development，沿用已授权直接施工；主控整合审查和静态发布，不提交或推送。

**Goal:** 新增现场账号遇到不符合既有密码长度要求的输入时，页面明确说明原因，并在发出创建请求之前阻止提交。

**Architecture:** 保留API用户账号16–256位密码规则，后台账号表单增加同样的长度约束与中文反馈。创建仍必填，编辑留空仍不更改密码；不改变RBAC、账号启停、会话失效或现场任务流程。

**Tech Stack:** React / TypeScript / Vite；现有form序列化及字段配置。

**Spec:** 已批准独立平台设计与现有 `operations/admin.ts` users schema；本节作为小缺陷修复的范围记录。

## Evidence and scope

用户反馈新增FIELD账号收到VALIDATION通用错误。已核对接口要求16–256位，用户输入长度8，页面未展示长度要求；错误details也未展示。18:06后台只读查询用户名keqi_118尚不存在。requestId为错误响应生成编号，是否保留可检索日志按实际证据报告，不声称已复现同一请求。

采用表单与既有接口规则对齐；不降低密码下限，不以自行生成的新密码替换用户选择，不自动创建账号。新密码由用户在后台填写。仅修改frontend `resources.ts`、`form.ts` 与必要测试/离线QA。App已有新建密码必填检查，保持其逻辑；不增加HTML maxLength截断，统一由序列化校验给出明确中文错误。

## Global Constraints

仅在本项目写入，旧库不连接。用户实际密码不写入代码、日志、证据、测试或交付文档。保持生产API镜像/配置和H5不变。大批既有脏改动保持，静态包从已上线精确基线加本轮审定文件构建。

## Review Focus

- 新建空密码与1–15位拒绝，16位/256位接受，257位拒绝；不把密码拼入反馈。
- 编辑留空不发送password字段，非空新密码同样校验。
- 前后空格不得被客户端静默改变，以既有接口原值规则为准。
- FIELD角色与active正确保留，其他资源的必填、金额等序列化保持。
- 浏览器实际操作无效密码时不发创建/更新请求，正确显示具体长度提示。
