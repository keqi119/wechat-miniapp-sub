# 车辆详情工作台改造

日期：2026-11-03。用户已明确四项改造要求，并确认商品按各自选择复用检测记录；项目授权按方案生成计划后直接施工。

## 目标和范围

1. 概览去除重复事实，紧凑分组，1920×1080屏幕75%浏览器缩放下尽量一屏容纳主要信息，常规1440宽及390窄屏仍可读。顶栏保留车辆名称、车牌、状态和操作；概览三组为身份登记、电池与使用、采购合作。每项事实在概览主体只出现一次；不再叠加完整车辆资产卡、核心指标卡和最近状态卡。保养保留为紧凑辅助区。BaaS、电池归属、合作商等值提供有权限的关联入口，保留返回定位。
2. 权证资料显式显示登记证、行驶证、采购合同、发票四类卡片，可上传、查看和更正归类。用户同意取消旧“车辆私密原件”混合展示板块，已有原件及专用权限保留。根据后续明确要求，未确认归类的只放独立“待分类资料”tab，不在已分类页面显示待分类内容或列表；已有保险/BaaS等明确资料放对应页面。旧PURCHASE不能直接视为合同或发票，旧INSPECTION是年检，不能当三方车况报告，旧PHOTO不自动成为公开照片。
3. 新增车辆照片tab：选择多个JPEG/PNG，逐份上传并显示进度、缩略图、点击原图、设封面、排序/移除绑定；相册和封面复用Vehicle既有字段，同车商品使用同一份车辆照片，无复制上传。保留20张/每张10MiB既有边界。失败保留成功项目及未知结果对应幂等键，不自动重复上传；图片预览随车辆/会话变化失效并撤销object URL。
4. 新增车况查验tab：多条三方检测记录，含标题、检测机构、检测日期、文字描述和图片。每条独立版本，可新增、编辑。未选择资料仅后台管理员/运营可读。现有conditionDisclosure保留，原车况披露和上架要求不自动替换。
5. 商品展示：每商品独立勾选0至20条本车检测记录，保存时校验源版本并冻结文字和图片快照；修改源报告不自动更新已展示内容，需重新选择保存。空选择关闭复用。保留商品版本、幂等、价格和产品来源保护。公开输出按商品，不合并到车辆全局报告；商品隐藏/下架或车辆未发布时不得公开检测图。

## 实现选择

复用现有React/AntD/NestJS/Prisma、车辆与商品生命周期；新增独立私密检测记录和文件绑定，原照片仍使用车辆公开素材。避免直接修改原件用途，也不另建第二份商品相册。相比只重排页面，此方案能够持久化车况复用与安全的批量上传；相比整体重写详情页，保留既有业务组件和授权边界。

从当前线上冻结版本20261103-vehicle-publish-readiness-v1复制独立工作目录 `.runtime/vehicle-workspace-20261103/workspace`。根工作区存在未发布签章/密码策略改动，不能整仓构建发布。所有实现先在副本按文件分工，测试和复审后再精确合并。根依赖安装、锁文件和发布由主控负责。

## 权限与数据约束

- 原件、检测资料仅ADMIN/OPERATIONS；普通车辆权限不能自动获得所有私密附件权限。
- 图片上传及绑定均校验真实格式、大小、所属车辆、用途。私密原件ID不能直接放入图库或公开检测图。
- 图片绑定继续受车辆revision、幂等、事务和订单占用保护；私密检测记录可独立编辑，不隐式改车辆商业状态。
- 商品保存源版本快照，采用现有商品revision冲突规则；不改产品价格或产品版本来源哈希。
- 金额整数分，零值不当缺失。会话变化/403清空私密内容；503保留同一作用域的上次数据并禁写。
- 不删除2,003份历史原件，不做照片归属批量迁移。该任务等待用户分类命名，四组跨车相同照片继续待核。
- 无真实交易、签章测试，不连接旧库。生产验收不创建虚构车辆、检测报告或商品。

## 验证与交付

先失败测试再实现；覆盖实际页面交互及API事务/RBAC/归属/版本/幂等、公网未选/隐藏/下架拒绝。概览使用含长公司名称和缺项的合成记录验证密度，保存截图并检查关键事实不重复、文字未裁切；保留tab滚动/输入/返回定位。

新增迁移只做兼容性增量，旧商品检测选择默认空；部署前验证精确来源、迁移、构建及独立代码复审。上线后只读核对真实车辆字段/原件数量未改变和静态资源生效。小程序选中商品的检测展示如需接线，保持现有视觉并单独验证，不混入未发布签章代码；不得把仅API成功称为手机实机验证。
