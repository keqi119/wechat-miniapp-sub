# 车辆、保险与后台导航调整

用户已明确要求并授权计划后直接施工。本设计补充同日车辆资料卡设计，沿用已发布冻结源隔离施工；旧仓库只读 Git 对象，不连接旧数据库，不恢复 OCR，不修改小程序。

## 保单登记

保单列表按车牌、VIN、车型、类型、保单号、有效期、保险机构、被保险人、当前状态展示。多车保单保持车辆信息一一对应；缺失值显示未登记。筛选在服务器执行，不对当前页假装全量筛选。

新建和修改采用同一基础表单，原件和批单在表单附件区拖入，一次保存。取消逐条险种、全文条款输入、独立复核和提交生效步骤。修改必须说明原因；每次保存形成不可变版本、文件证据和操作记录。点击附件通过专属鉴权接口打开。

新增 REGISTERED 版本表示操作员登记的事实，不冒充旧 APPROVED 独立复核。历史审核人、审核项和原始内容保留；新模式保障判定按真实登记、车辆、日期和文件证据核对。迁移冻结历史版本当时的保单号和机构；后续修正当前保单身份不得改写历史。登记、附件和根记录修订在一个幂等事务中完成；保留 RBAC、版本冲突和当前会话验证。

## BaaS 与车辆台账

BaaS 参考原仓库的紧凑列表，明确合同、车辆、出租方、状态、周期租金及付款日。月付、季付、年付如实显示；下次应付和未支付只取本项目实际成本计划、成本与付款事实，未生成计划不得显示已结清。不改变启用、暂停、终止、试算及财务确认的业务约束。

车辆列表在车牌、VIN、车型附近展示电池容量和电池方式。容量来自资产档案，保留小数；方式区分电池买断、BaaS / 电池租用、未登记。车辆状态按当前系统真实草稿、上下架、预留、用车状态标注，不套用旧系统不同含义的枚举，不推断容量或占用原因。

## 导航层级

牌照档案、保养提醒、内部工单在车辆管理下与车辆台账平级。恢复既有业务导航定义中被展示投影合并的独立模块，包括保险 / BaaS、估值 / 折旧以及订单、财务的独立业务入口。侧栏选中真实当前模块，保留原 hash、筛选和记录深链，不改变权限。

同一实体的概览、附件、明细等仍是详情标签。独立业务列表不得以某个兄弟业务名称作为侧栏代表。无权访问的叶子和空分组不展示。

## 验证与发布

重要业务先写失败测试：登记及修改历史、并发与未知结果、真实保障状态、附件归属；导航选中与权限；电池未知值。完整构建后独立审查。发布仅使用冻结源与本轮增量，备份并验证恢复，保留旧静态资产及现有域名配置，不混入其他未发布代码。
