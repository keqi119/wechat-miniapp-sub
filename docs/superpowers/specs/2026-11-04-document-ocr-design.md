## 范围与选择

采用 RapidOCR CPU 本地识别服务 + API 字段解析 + 两端现有表单回填。无需付费识别 API，不发送文件到第三方。相比规则直接处理客户端文本，服务端从已授权原件取字节并校验摘要；相比本地大模型，CPU 方案资源较小且字段证据可追溯。多版式仍需真实样本调优，不承诺未经实测的准确率。

- 后台登记证/行驶证：VIN、车牌、登记人、发动机号、颜色、首次登记日期。发票：购销双方、票号/日期/金额，票面金额不能自动视为实际采购价。保单：公司、保单号、主体、期间、险种与保费。采购合同/BaaS第一版保留上传，不猜测自由条款。
- 小程序身份证人像面/国徽面、驾驶证：识别字段在各自卡片内展示；补充现有姓名和驾龄，身份证号只进入当前页面内存及已有实名输入，不进入缓存、日志、后台 DTO。其他证件信息供核对，保持现有资料存储契约。
- 原件可为 JPEG/PNG/PDF；PDF最多8页、单页渲染受像素限制，超过限额明确返回；统一按页渲染识别，避免混合PDF中的页脚文字层掩盖扫描字段，并保留字段位置依据。模型在服务启动前准备到本地；请求阶段不能下载代码或模型。

## 数据和交互

OCR是只读提取动作；从本车绑定原件或本人上传文件取字节，不接受客户端路径/URL/OCR文本。服务返回字段值、页码/原文/识别分数、缺项及冲突提示。每次输出重核会话、文件绑定及摘要，响应 no-store；不保存完整 OCR 文本或证件号码到审计。

各卡上传后可触发提取，已有文件行内可再次提取。后台识别结果在卡片内编辑、核对后使用现有资产/保单草稿命令保存；已有非空不同值明确提示，VIN 不符阻断归入本车，现有 VIN 不可由 OCR 替换，车牌变更沿用牌照办理。保险原件需通过保单专用上传绑定才能进入保单草稿，不能仅把车辆文件ID冒充专用保单原件。

小程序识别只补空值；请求期间人工编辑、换文件、换用户、卸载及后发请求使旧结果失效。数值0不是空值。成功回填仍需原有资料保存；OCR不代表实名或驾驶资格核验通过。失败保留原件和输入、允许人工录入。

## 架构接口

- `POST /api/admin/vehicles/:vehicleId/documents/:fileId/ocr`，JSON `{}`，类型由服务端分类确定。
- `POST /api/customer/profile/ocr`，JSON `{fileId,slot}`，slot为 identityFront/identityBack/drivingLicense。
- 返回 `{version:1,fileId,documentType,fields,evidence,warnings,sourceSha256,vehicleId?}`。fields为字符串字典；缺失不填。evidence是字段名到 `{page,text,confidence}` 的字典，confidence为0至1。
- 内部 worker：`POST /recognize`，Bearer共享密钥，JSON `{data:base64,mimeType}`；返回 `{pages:[{page,lines:[{text,confidence,box?}]}]}`。只内网开放；配置缺失503，无Mock回退。并发1、文件32MiB以内、超时及响应大小上限。
