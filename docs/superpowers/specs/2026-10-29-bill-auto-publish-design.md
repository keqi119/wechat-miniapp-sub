# 合同账单自动发布设计

用户要求合同生成的草稿账单按系统时间，在到期日前3天自动发布，取消逐单人工发布。沿用现有线下签约、归档审核和客户主动支付流程。

## 业务规则

- 自动范围为合同生成的 SUBSCRIPTION（租金）与 DEPOSIT（押金）DRAFT 账单；金额与到期日仍来自已确认方案。附加费用、还车结算、超里程和权益购买等专用流程保持原审核规则。
- dueDate 为数据库日历日期。预计发布日期为该日期减3个日历日，采用北京时间；当天00:00进入窗口，后台每分钟扫描，正常情况下1分钟内发布。跨月、跨年按日历计算。
- 发布窗口已到且合同已归档/签署就绪时，系统将 DRAFT 转为 PENDING。合同晚归档、服务重启或任务暂时失败，下一次扫描补发。
- 已取消/已完成订单不得发布。保留线下合同版本一致性及反馈阻断、有效电子签历史合同、订单变更资金安排、实物收车与正式归还未履约期间保护。已履约但未支付账单不因进入结算阶段全部阻断。
- 发布仅改变应付状态并发送站内通知，不调用支付渠道扣款，不新增租金、不重算金额、不自动审核合同。
- 同订单加锁、重读账单、状态条件更新；状态更新、SYSTEM/AUTO_PUBLISH审计和站内通知在同一可重试串行事务提交。重复任务、重启或并发实例不得重复通知。
- 分批按主键游标扫描，业务阻断和单条异常不影响其他订单；安全错误日志不包含客户、凭证或数据库连接信息。

## 页面与接口

后台账单列表、详情及订单资金页面显示 publication 只读字段：mode、scheduledDate、state、message、blockers。自动账单不再提供常规人工发布入口，手工API对自动类型返回明确提示。显示预计自动发布日期、待自动发布、业务阻断或已发布状态。草稿不提前出现在客户应付账单中。

投影复用无写入的业务校验，读取不能提升订单revision。执行时在订单锁内再次验证真实状态，不能依赖页面投影放行。

## 发布控制

BILL_AUTO_PUBLISH_ENABLED 必须显式为 true 才启动定时扫描。切版时先保持关闭，完成原数据保全和API检查，再单独记录启用时刻并启用。启用后对符合窗口的现有草稿进行预期补发，单独核查审计/通知及其他数据未变化。无数据库迁移；只部署独立宁达平台，不变更小程序包。
