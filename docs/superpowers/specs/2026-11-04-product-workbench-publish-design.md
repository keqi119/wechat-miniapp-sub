# 产品工作台、产品仓库及商品发布校验

用户于本轮明确新增要求；沿用本项目计划后直接施工授权，与车辆资料、保险和导航增量一并验证。

## 产品页面

产品仓库是唯一产品列表，用状态 Tab 区分全部、草稿、已发布、已暂停等真实状态。筛选基于实际版本状态，由服务端处理或读取完整可核对集合，不能把当前页筛选伪装成全量。保留搜索、分页、查看版本及既有权限。

产品工作台改为一级整页表单，展开原新增产品抽屉：基本信息、基础费用、里程包、换车权益、适用车型与车辆、附加服务分区；桌面双列、窄屏单列，车辆筛选表独立滚动。复用现有金额分、版本、草稿保存和发布校验，不复制一套相似列表。已有产品记录深链继续可访问，旧详情入口兼容后导向明确的仓库详情或工作台编辑，不丢失记录。

## 商品发布的七项条件

1. 车辆基本信息完整，显示确切缺失字段和补录入口，不要求发动机号等全部选填资料。
2. 本车已明确关联合作商，合作商必要主体与联系资料完整；信息齐备与合作协议生效是不同事实，既有签约/订单资格规则保持。
3. 已匹配至少一个真实生效产品版本，适用范围、版本源摘要及套餐来源有效。草稿商品可承接已发布的产品版本，避免车辆上架和商品发布互相等待。
4. 发布时刻（页面按上海发布日显示）交强险及商业险均有效；不要求在发布时覆盖全部未来租期。险种类型来自明确登记或旧已审事实，不从文件名猜测。
5. 实际车辆相册至少一张，商品共享封面至少一张；同一张有效车辆图片可以兼任相册与封面。
6. 电池方式为 BaaS 时，本车当前 BaaS 必要信息完整；本轮不额外要求启用、记账或付款。买断车辆此项不适用。
7. 基本车况已明确记录火烧、泡水、结构性损伤三个是/否判断。未填写不通过；“有”是合法的真实判断，不等同缺资料。详细报告、图片、全文披露不作为额外强制项。

## 基本车况及前后端一致性

新增每车当前基本车况事实，首次不冒填历史值，三个判断必须显式提供。修改需要说明；当前人员、车辆与评估双版本、事务幂等及前后审计均保留。车况查验 Tab 顶部直接填写，详细查验记录继续可选。

共享发布 readiness 服务返回固定七项及缺失原因，车辆商品页逐项呈现；商品发布与车辆上架在事务内重新核对，不能仅禁用前端按钮。现有状态机、占用、权限、版本冲突、来源一致性和幂等仍执行。基本车况须如实进入客户可查看的商品披露，避免登记了损伤却展示为空；旧商品报告快照与摘要不得被改写或伪造。

## 验证

测试缺失任一项禁止发布、无 BaaS 时不误拦、保险起止边界与旧未知类型、真实照片归属、布尔 false 计为已填写及 true 的披露、详细报告完全空白可通过。产品工作台测试整页排版、仓库状态切换、保存后回读、未知结果冻结、旧记录深链及只读权限。完整构建、隔离库迁移和审查通过后才制作发布包。
