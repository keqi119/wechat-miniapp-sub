# 企业合作商中心分阶段办理页面

2026-11-09：用户已批准对话中的三 Tab 方案并授权直接实施，补充要求“页面 UI 一致；企业认证已通过不再给按钮重复认证，除非认证过期”。本文件记录已选方案，归属 V3.1 真实渠道验收 Task11g。

## 选择与范围

采用现有企业中心、公司信息栏和三个一级 Tab：**实名与印章、合同与协议、自动用印**。自动用印内分别显示“独立用印授权”“法大大签章授权”，内部权利、签署、归档和启用规则不合并。曾比较四个一级 Tab；三 Tab 减少移动端相似授权入口，用户已选三 Tab。不新建入口，不重做全站，不新增财务或自动签能力。

## 布局和状态

- 复用原企业中心黄/黑/米白配色、卡片、primary/secondary/text 按钮、Tab、Modal/LegalDialog 和响应式尺寸。移除 legal.css 对全部按钮和卡片的冲突覆盖；不要再让内容被全局 state-card 固定宽度约束。
- 公司列表显示公司卡片和可核实标签；进入后只显示一个公司信息栏，含名称、统一信用代码、法人、脱敏手机号、认证和印章标签，提供返回公司列表。消除重复公司卡片+下拉框。
- 实名未完成：协议标题链接打开浮窗，主动勾选后开始认证；认证中/结果未知显示继续办理或查询，明确失败才允许按现有渠道方式重试。切换公司、返回、失败均不得复用过期同意或旧请求结果。
- 当前企业和法人已完成认证：展示“企业认证已完成”和完成时间，完全移除开始认证按钮及认证勾选框。签署证书缺失、过期、核验时间超过24小时只能显示更新核验，不冒充企业实名过期。
- 现有渠道 projection 没有单独企业实名到期日，禁止编造有效期或把证书到期当作实名过期。没有明确、可验证的实名过期依据时，不开放已通过企业的重复认证。公司或法人认证材料实际变更后，按下述补充要求重新认证，不以查询旧证明代替。
- 认证成功后突出选章下一步。通过既有受保护图片接口展示真实印模，图片失败可重试；用户阅读印模后明确“确认使用此印章”，成功回读后显示“印章已启用”。既有 ACTIVE 选择保留并展示，不自动替换或代用户确认。提供查看/更换；异步图片、确认和成功提示必须绑定当前公司、印章和图片摘要。
- “印章已启用”表示本平台确认选用。自动用印状态独立；本轮测试仍为逐份本人签署，不把自动用印未开通当作实名失败。
- 合同 Tab 展示真实待办和已签署/归档记录，空列表给明确空状态。已完成文书不显示签署阅读勾选和启动签署按钮，保留文件和记录。已有撤销/查询等合法操作按原权限保留。
- 自动用印 Tab 内授权仍分两块；使用业务名称和简洁说明，去掉大段内部“02/03—06”指引，原内部 ID 不作为按钮文案。已完成或不可申请状态不显示无效勾选和申请按钮，但保留结果、原授权管理能力与阻塞原因。
- 协议浮窗独立滚动、版本清楚、关闭后回到触发控件；不自动勾选，不以打开窗口冒充同意。标签可键盘操作，移动端不横向溢出。

## 用户补充：认证材料固定及变更

2026-11-09 用户进一步明确：“认证通过后的法人和公司材料需要固定下来，如果发生法人和公司材料发生变动的，则要求重新办理企业认证。”以下补充已纳入本轮实现及独立复审。

- 固定企业类型、名称、信用代码及法人姓名、手机号摘要、原始材料摘要和版本，保留旧认证证明与审计记录。普通业务联系人和文书联系地址不属于认证材料，不因修改这些信息而重新认证。
- 真实材料变更后显示“资料已变更，需重新认证”，暂停新签署和两类自动用印，并取消当前印章选择。新资料必须由当前法人重新同意并取得新认证流水；继续沿用同一企业渠道账号，旧流水查询或回调不能恢复新资料的认证状态。
- 信用代码或企业主体类型变化不能覆盖已注册主体，应建立新主体档案；不自动迁移原协议或车辆。未解决的认证请求先完成或人工核对，避免并行发起和重复收费。
- 新认证通过后重新预览、确认印章；原自动用印授权不自动恢复。已签合同及历史记录保留。未变更的既有已认证企业保持现状；旧记录首次固定材料时标明实际采集时点，不伪造原认证时点材料。
- 同资料认证中断后继续原认证地址，不新建流水。回调原流水必须贯穿到事务预留校验；旧回调和新认证交错时，不得查询或修改新任务。
- 后台现有资料表单增加对应说明；保持原表单样式，不新增审批流程。

## 技术边界

继续 React/TypeScript/Vite H5、Nest API 和既有 DB。范围包含页面编排、认证状态投影、重复启动保护及用户补充的材料固定、实际资料维护入口失效处理、认证回调原流水绑定和必要后台提示。复用现有 JSON 与审计记录；不改模式开关、签署/支付回调、既有岗位权限、资金规则、法务正文、数据库 schema/migrations/dependencies。

增加明确的认证完成事实投影，不用原 readyForSigning/certificationComplete（含证书新鲜度）表示永久实名事实。已有业务 freshness 门禁继续生效。服务端对当前同主体已通过的重复启动请求应在任何同意写入/供应商调用前拒绝或无副作用返回，不能只依赖按钮隐藏。
