# 车辆上架缺项与商品展示状态修正

用户反馈沪BAX1511商品已发布、App不可见，车辆上架返回PUBLISH_REQUIREMENTS。按项目已确认的直接施工授权执行。

线上只读核实：车辆仍DRAFT、conditionDisclosure为空；对应商品PUBLISHED且visible=true，兼容套餐active=true，产品版本PUBLISHED。公开目录仅返回PUBLISHED车辆，故本例直接阻塞为车况披露缺失。商品发布和车辆上架是不同生命周期，保留此规则。

修正范围：

1. 车辆上架保留真实车况披露、有效套餐、已发布产品、占用、VIN、权限、修订号、事务与幂等校验；将车况及套餐缺项提示分别说明，不再把单一缺项提示成同时缺两项。
2. 后台只对真实版本冲突显示记录已更新提示；业务条件409显示原业务错误并保留输入。
3. 产品卡槽区根据车辆状态提示实际App展示前提，将商品visible明确称为展示设置，避免商品已发布被解释为整车已上架。
4. 核对本车已归档检测资料，仅以确定事实形成车况披露；缺少可靠事实时向用户确认，不编造无事故、无水泡、无火烧等结论。具备真实披露后，仅通过正常API补齐本车并上架，保留产品价格/配置和其他车辆状态。

非目标：不放宽上架、申请、有效合作或交付条件，不修改套餐、合作协议、原件和其他车辆，不发布小程序新包或混入未发布工作树改动。

发布从当前生产20261103-vehicle-partner-source-v1冻结源码追加精确差异；operations/admin.ts工作树另有未发布密码规则，不能整文件带入。本轮不改数据库schema或迁移。

验收：先复现失败测试，再修正；涵盖车况单独缺失、套餐单独缺失、全部满足、原交易保护、业务409与修订冲突区分、车辆未上架时商品提示。发布后核验真实API状态、公开目录/详情及后台静态包；车况来源与本车写入前后回执保存在项目.runtime中。
