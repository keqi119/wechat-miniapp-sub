# 个人资料排版与实名入口修复

2026-10-29。按用户已授权直接实施的基线及本轮明确反馈施工，不新增业务流程。

## 本轮目标

1. 修复实名调用在底层被电子签关闭开关误拦截的问题。实名独立可用，电子签和用印继续关闭；本人完成实名，系统只接受可信查询或回调结果。
2. 个人资料按基本信息、分类证件、实名核验组织，沿用黄黑色与简洁卡片。减少重复标题、长说明和大尺寸次要按钮，主要动作就近排列。
3. 未分类历史附件退出个人资料办理：不展示、不提供选择、不自动归类或加入提交。已有明确分类证件继续保留。此次不清理被历史订单或审计引用的底层文件。
4. 隐私政策在每种可见页面状态仅保留一个阅读入口，使用当前正式版本。登录/协议更新的同意与实名核验的单独同意继续分别记录，不自动勾选，不修改正式文案。
5. 点击反馈使用当前视口浮层，长错误可读且可关闭；不把操作结果堆到页顶，不滚动页面。保留字段、草稿和阅读返回位置。
6. 电话旁使用拨号图标，退出位于末尾。原补件、地点建议、定向支付验收及返回申请行为不丢失。

## 实现选择

实名采用独立调用上下文及最小供应商接口白名单，避免重开电子签总开关。资料页在现有原生页面内整理，不引入新页面或UI依赖。使用已有服务端资料版本、实名状态和文档版本约束。

本次实名修复只更新API，兼容已上传1.1.6；页面优化另上传1.1.7。后台/H5静态文件、已有数据及业务配置保持当前版本，不做迁移。

## 验收

- 真实Controller→实名服务→供应商Client/Http调用链，最外层合成transport验证OFFLINE实名到达允许接口、签署和证书仍拒绝。
- 页面行为验证历史附件不再流入资料/提交、反馈在当前视口、失败及重试保留输入、会话变化隔离、同意门槛有效。
- 320/390宽合成排版检查，以及小程序回归、源码检查和模板编译。
- 发布仅独立服务器，保留15个静态文件、123张表及已有环境配置；备份恢复核验后切换。
- 上传不等于体验切换或本人实名通过；真机结果由用户确认。
