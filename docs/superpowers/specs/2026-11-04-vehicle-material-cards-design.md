# 车辆资料卡拖拽与紧凑列表

用户已明确交互和目标；依据本项目 AGENTS.md 的计划后直接施工授权实施。本轮为独立的资料操作改造，不恢复已放弃的 OCR。

## 用户需求与范围

车辆台账详情的权证、保险、BaaS、待分类原件采用同一种卡片：整张卡接收文件拖拽，直接按卡片类别上传；卡片内部显示紧凑列表，点击文件名打开，仅保留删除操作。移除独立上传表单、原件搜索/筛选、下载按钮、调整分类与“添加xxx”按钮。卡片显示名称、份数和简短拖拽提示；列表显示文件名、类型/大小，完整文件名与来源可通过提示读取。

车辆照片、结构化车况查验使用独立业务流程（含公开展示选择、20张限制和查验快照），本轮不把它们的业务编辑动作替换成无条件文件归档。其余业务卡的新增合同/保单按钮也不属于原件上传按钮。

## 实施取舍

沿用 React/NestJS 和现有原件上传协议，不引入上传依赖。与保留底部上传表单或只把按钮移到卡片相比，卡片直接承接拖拽满足用户明确要求。键盘聚焦卡片后 Enter/Space、点击简短提示或触屏点击提示可触发隐藏文件选择器，不增加可见上传按钮。

每次拖入支持多个文件，逐个上传并回读确认后才处理下一份；每份冻结自身幂等键和 FormData。32MiB 和 PDF/JPEG/PNG/DOCX/MP4 限制不变。默认来源路径使用 `manual-uploads/<本次幂等键>/<文件名>`，保留原始文件名，避免同名文件或软删除后重传冲突。传输未知失败使用原请求重试，收到成功回执后只回读；版本冲突停止队列并重新核对，不能自动基于新版本重发旧请求。换车、换视图、换账号或失权后不得继续处理迟到结果。

文件打开使用专属授权 `/documents/:fileId/open` URL，在浏览器新页原生打开 PDF/图片/视频；DOCX 由浏览器下载/本机 Office 处理，不使用第三方在线阅读器。原下载接口保持原有附件响应。新链接只由可信 API base 和本车/文件 ID 构造，保留账号、车辆归属、no-store 和 nosniff。

## 删除与数据边界

新增带确认的软移除。VehicleDocumentFile 增加 nullable `removedAt/removedBy`，保留绑定行和 StoredFile/磁盘字节；绑定也是通用文件读取的永久隐私边界，不能物理删除。列表过滤已移除项；专属打开/读取/分类拒绝已移除项；其他通用/公网隐私检查仍计入这些绑定。操作仅 ADMIN/OPERATIONS，复核当前人员会话、父车辆 revision、documentRevision、车辆锁、事务幂等与审计；仅 documentRevision 增加。幂等重放先于 active 绑定检查。

## 验收

卡片拖入正确隐式类别，多文件串行版本正确，无额外上传/搜索/分类/下载按钮；列表文件名可打开正确私有原件，DOCX fallback 明确；删除取消不写、确认后仅消失于列表，历史原件与隐私边界保留。覆盖迟到结果、会话/父详情失效、未知上传/移除结果、成功后回读失败及同名重传。1440/390 布局检查无横向溢出。

工作在项目内隔离副本中，以当前已发布冻结源为基线，只合并本轮清单增量。根目录其他未发布变更、微信小程序和已撤回 OCR 均不混入。
