## 方案选择

采用独立车主身份模块和按签署角色记录的新合同任务。复用现有平台 API 凭据、HTTP 摘要构造、PDF 坐标、微信内嵌页、主动核验及文件归档。

不采用全局替换晓浪企业 ID 的做法：同一平台会有多个车主，旧技术验收仍由晓浪签署。不引入旧系统数据库作为依赖：车主在本系统独立认证和关联，旧项目仅为只读参考。

## 企业身份与用户归属

1. 运营建立企业车主草稿，录入公司全称、统一社会信用代码、联系地址及经办人邀请。实名证件由本人在法大大页面提交；本平台优先不保存法人身份证照片和银行卡原文。
2. 车主经办人用现有微信/手机号登录，经验证手机号匹配邀请后认领。邀请有期限、一次性 token 的摘要、公司绑定，不能凭链接改公司或领取其他车主资料。
3. 经办人阅读企业认证信息处理说明并单独同意后，平台在现有法大大应用下注册独立企业账号，取得企业实名 URL，由法人或代理人本人完成认证。
4. 主动查询企业认证、实名绑定、证书及印章；名称和信用代码必须与车主记录一致。未知/缺失/不匹配时停留待核验。
5. 经办人身份与法大大企业管理员身份应匹配或有可核验代理授权。平台管理员建档或短信认领都不能独立证明有权代表该企业。
6. 企业认证结果、证书和印章分开记录。更换企业主体必须新建身份；更换印章使未执行的用印准备失效。

拟新增 `VehicleOwner`、`OwnerMember`、`OwnerInvitation`、`OwnerESignAccount`、`OwnerSeal`。身份敏感字段加密或散列匹配，接口只返回必要脱敏字段，原始认证响应不进入日志。

## 车辆、订单与合同主体

- 车辆明确关联企业车主；运营审核车辆归属/使用资格材料。不能仅凭保单名称自动完成审核。
- 最终方案保存不可变的车主主体快照；客户确认时一并确认出租方。建立合同后变更企业或车辆归属，需要新方案和新文档确认。
- 合同正文、订阅方案、延期/换车补充协议、签署页、后台及小程序均显示真实出租方。晓浪作为服务平台的说明独立列明。
- 交还车仍由平台统一承接：交接事实文档须清楚标注实际交接人员及其角色，不能把平台作业签名当成车主合同签名。涉及租赁权利义务变更的协议仍由原出租方签署。
- 新任务的签署角色使用 `OWNER`、`CUSTOMER`；平台自身协议继续使用 `PLATFORM`。历史任务沿用原字段和证据，不批量改写。

## 手动与自动签署

### 手动

默认模式。经办人仅能看到自己有权处理的企业文件；查看全文及 PDF、确认当前文档摘要，然后进入法大大企业签署页。订阅用户仍使用自己的个人实名身份签署。平台不代替车主点击同意或完成验证。

### 自动授权

车主主动发起法大大授权委托书签署。回跳只触发查询；查询证实指定企业账号、授权合同和交易流水一致，且授权有效，才能启用本地开关。

本地开关默认关闭。授权范围需由车主明确确认：企业和印章、允许车辆、订阅主合同模板版本、有效起止时间、月租/押金范围及期限范围；金额均为整数分。权限不自动覆盖延期、换车、还车结算或新版本条款。这些文件首发保持手动确认。

自动执行还须满足当前方案已通过运营复核、承租人已确认并完成本人签署、身份与文档未变、车主开关仍开启、每次执行前渠道授权状态有效、证书有效、合同在车主授权范围内。

每份合同保留“本份改为手动确认”。手动入口一旦领取，冻结为手动模式，禁止后台再自动盖章；自动请求一旦发出或结果未知，不能转手动重新签署，先查询原交易结果。关闭开关立即阻止新的自动请求；已发出的请求按原交易号核验，不声称可以撤回已完成签名。撤销法大大授权单独显示渠道结果，失败时本地仍保持关闭。

本地开启需要车主本人操作；运营可暂停，不能代车主打开。现有晓浪印章的双人复核仅适用于晓浪自身用印，不充当车主自动授权；运营文档审核与车主签署授权分开记录。

## 任务与完成条件

新增独立 `OwnerSigningTask` 与 `OwnerSigningParty`，保存合同/订单/企业快照摘要、源 PDF 摘要、签署坐标、两方 providerCustomerId、企业 signatureId、每方稳定交易号、模式及授权证据。

- 上传和用印各有处理租约；外部调用不得放进自动重试的数据库事务。
- 请求发出前持久化执行意图；超时或未知结果只查询同一交易，不能换号重签。
- 回调验签后仍核对任务、合同、签署方和文档绑定。签署完成需可信查询确认双方已签，并保存带摘要的签后 PDF。
- 只有完整证据可推进订单至支付/交付；回跳、按钮点击、单方签署、文件下载成功都不能单独标记双方已签。
- 车主不能读取其他车主合同；客户不能领取企业签署 URL；平台管理员不得冒用企业经办人接口。

## 前端与文案

后台新增企业车主、经办人、实名/证书/印章状态、车辆归属与合同签署进度。小程序“我的”中为已认领经办人显示企业签署工作区，包含认证入口、授权开关、范围、逐份文件列表。不开车主结算经营后台。

客户最终方案和合同页显示出租企业；签署进度分别显示客户/车主。继续复用已验证的微信内嵌、签后返回及 PDF 查看功能。

新起草车主认证/授权说明、车主-客户订阅合同及平台用户协议/隐私必要增补，交用户审阅后发布；现有批准不扩展为新文本批准。位置隐私 v3 微信申报仍未完成，地图权限仍在申请中，不把这些状态改为已完成。

## 验收与上线门槛

1. 新增模块使用独立测试库与供应商模拟传输完成越权、错企业/错章、过期授权、主动撤销、重复回调、并发手动/自动、超时恢复测试。
2. 保持既有技术签署及个人实名回归通过；新旧两套任务互不改写。
3. PDF 逐页检查真实出租方、两方签署框及补充协议主体；后续真签检查落章。
4. 企业有权经办人完成真实认证、企业印章核验和手动签署；自动模式须本人另签授权后再验收。
5. 首笔真实租赁仍需实际承保用途等逐单材料。租金 12 期各 0.01 元、押金 0.01 元仅用于已指定受控验收订单，不改变公开套餐。
6. 功能部署默认关闭真实车主认证/签署入口；法律文本批准、企业归属核验及受控名单就绪后分步开放，不宣布未做的真实验收通过。
