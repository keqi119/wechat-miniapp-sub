# 独立里程包与目标车型换车权益

用户已授权直接实施，确认本轮只做里程包、换车权益；补能包暂不开发。与先行后台界面修正分成独立增量验证，旧仓库和旧数据库不参与开发测试。

## 用户确认的规则

- 商品中心下“车辆基本套餐、里程包、换车权益”平级。主套餐工作台、产品仓库仍管理主套餐版本，不能把独立加购商品伪装成新的主租赁套餐。
- 客户必须有本人真实正在履行的主套餐订单，且实际当前服务段已生效、未收车。入口放在小程序“用车”。后端再次核验资格，按钮不是授权。
- 里程包为1000、1500、2000公里三档，后台按多选品牌/车型维护真实总价。里程越大，每公里单价严格递减，使用整数交叉相乘校验；不沿用旧种子价格，不自动补价。
- 月包仅购买时所在计费月有效，计费月来自 UsagePeriod；同月换车随主订单继续使用，期末不结转。原月延后核验、结算仍可抵扣该月已付月包；已结算后一次性记剩余失效流水。
- 换车权益按一次计价，适用范围与价格按希望换入的目标车辆品牌/车型确定。下单冻结目标车型与范围，实际预占和完成换车必须核对；费用不包含车辆升级差价。
- 新商品及新价格不改写已有主套餐赠送、旧付费权益、原合同附件与法律hash。旧未决购买、真实到账、退款和历史结转仍按其原始来源核验。

## 配置与交易

独立商品具有草稿、已发布、暂停、退役及不可变版本；范围按品牌分组，明确全系或指定多车型，以OR组合。有效报价范围重叠时拒绝歧义定价。空价可以存草稿，不能发布出售。管理员、运营维护价格与范围，财务继续交易核账与独立退款职责。

复用当前微信账单支付、验签、金额/商户/订单校验、幂等回调、退款及权益账本，不接新支付渠道。下单冻结SKU版本、价格、计费月/服务段、车辆来源与功能说明hash，客户端不能传金额覆盖价格。新月包单独采用V2购买规则，不全局修改旧usageRules。

月界、收车、结算或来源失效后禁止新购买和再次发起无效付款。可靠渠道成功时间在原月内、原月尚未结算的晚通知可计入原月；月末后成功、已经结算或失效来源的款项仍记真实成功、零发放并进入核账退款闭环。不能让可信到账事务因授额异常回滚，不能转到下月或自动重算已结算费用。

## 页面与恢复

统一保持语义清楚、分类合理、紧凑和高信息密度，深度不超过3层。后台以列表直接展示价格、范围、售卖版本、状态和动作，新增/编辑在同页展开；版本历史按需折叠，不设多余详情页按钮。

2026-11-05 人工验收补充：保单类型、当前状态、选择车辆及到期提醒使用框内灰色占位提示，保留可访问名称；查询与刷新和筛选同排，类似的保险/BaaS、车辆、产品筛选条采用一致紧凑布局，窄屏自然换行。产品工作台取消整页表单居中限宽，桌面全宽左右布局，基本资料、费用与附加服务在左，车型与车辆范围在右；主要配置一屏可见，长车辆列表在自身区域滚动，保存操作始终可见，窄屏单列。

车辆台账另增加合作商、里程范围、电池方式、车龄范围组合查询，由服务端过滤全量台账后分页计数。合作商沿实际业务关联，车龄按真实首次登记日期计算完整月；未知不作为零值，范围非负且起止有效，保留既有搜索与状态条件。

BaaS 合同主搜索按 VIN/车牌，出租方、车辆品牌、车型、承租人支持录入或选择已有值；筛选、计数与分页一致，详情内的车辆限定不被全局筛选覆盖。电池规格直接显示合同 batteryPackage，承租人直接使用 lesseeName，不以车辆登记人或当前用车客户代替；选项接口不返回收款账户等无关资料。

小程序沿用明朗原生黄白视觉，在用车页进入加购列表，同页选择档位或目标车型、核对总价/期限/说明，确认后进入既有账单支付。区分待付、处理中、真实已付、失效、退款和待核账；旧记录按原版本显示规则。

未决创建跨页面保留当前会话内存中的原body/key，不存敏感FormData到浏览器持久存储；成功后只GET回读。注销、撤权清理私密输入；迟到结果不能改写当前路由或串入其他客户/订单。
