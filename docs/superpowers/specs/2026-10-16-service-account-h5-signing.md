# 原服务号 H5 签约接入

2026-10-16。用户在微信实际返回“校验文件验证失败”后明确选择“改用原服务号 H5 签约入口，签后回小程序同步状态”。本设计执行该选择，继续复用既有法大大 API、账号和企业印章。小程序网页嵌入及供应商补域名不再是本次实施路径。

## 页面与数据边界

入口为 `https://app.subauto.keybox.cloud/miniapp-sign/`，沿用原服务号 H5 主机。新目录独立提供静态页面，`/miniapp-sign/api/` 仅映射新系统 `/api/h5-sign/`。原 `/portal`、OAuth、数据库和菜单不修改。新入口不会复用旧客户会话或把服务号 OpenID 当作小程序 OpenID。同一主机意味着浏览器同源，并不宣称获得独立域名级别的脚本隔离。

用户从小程序签署入口主动复制无凭证的固定链接，在微信网页中打开，以新系统已有的同一手机号完成短信认证。H5 不自动注册客户，也不接受小程序 Bearer 或旧门户 cookie。独立 8 小时 HttpOnly、Secure、SameSite=Lax 会话 cookie 仅用于新路径；写操作同时要求精确 Origin 和 CSRF。验证码沿用新系统已有发送频控、次数和单次消费规则。

H5 只提供签约所需功能：本人记录列表和详情、实名准备度及本人发起核验、已审核文档查看、主合同/延期补充协议/交接签署、签后文件下载与状态查询。复用当前业务、归属、不可变文档、签章审批和外部任务恢复规则；不新增支付或代客签署。延期补充协议按变更 ID 调用专用逻辑，不能错误进入主合同交车流程。

## 外部页面往返

实名及签署仅在用户明确点击后发起，并按旧 H5 的浏览器重定向方式打开合法供应商页面。供应商通知仍发送新 API，返回地址固定为 `/miniapp-sign/return/`。服务端只允许明确批准的返回地址，前端不从任意 query 构造跳转。不记录完整签署 URL、身份证、短信或会话凭证，不把它们放入页面存储或入口链接。

返回页只发起可信状态查询。URL 中的 result、导航完成、用户回到页面均不证明成功；以供应商签名回调、服务端查询和签后归档为准。小程序保留本人业务记录、报价/事实确认和状态查询；回到小程序后刷新同一数据库中的结果。此切片不依赖自动唤起小程序，也不声称已新增服务号菜单。

## 实施与验收

1. API：专属会话和迁移 016、来源与 CSRF 校验、三类资源及文件归属、现有实名/签署服务适配、精确返回地址、公开入口配置。
2. H5：移动端短信登录、法律链接、签约列表/详情、实名、外部签署及返回查询；只使用独立 API。
3. 小程序：移除真实签署 web-view 发起与实名输入，改入口说明、主动复制及正确种类的状态查询。
4. 部署：新前缀 Nginx include、原 vhost 哈希和备份、仅新增路径、旧路径与新路径回归、数据库迁移和备份、配置敏感值不入库。
5. 验证：未登录/跨客户/来源/CSRF/旧凭证拒绝、无自动建号、三类业务守门、伪回跳不改变状态、文件归属、移动端布局与返回恢复。合成测试不发短信、不签署、不盖章。

实际短信、实名认证与签署由用户本人在具体页面完成；企业印章授权及双人审批仍按既有流程。真实业务验收与正式微信发布分别记录，不能用页面上线替代。
