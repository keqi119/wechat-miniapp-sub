# 宁达企业车主单方授权书

2026-10-21，用户明确要求以自行生成的单方授权书替换法大大 `before_authsign.api` 自动生成授权函；被授权人作为正文固定为“上海宁达信息科技有限公司”。按项目已授权生成计划后施工的约定开展本地实施。新正式文案仍须审定发布后启用。

## 范围

沿用法人 H5、已核验企业与印章、v2 授权期间和“汽车订阅主合同及同份 PDF 费用附件”类别。不按车辆、价格、套餐或期数限制授权。只设置车主企业的签章位；宁达是正文中的被授权人，无需宁达参与本次文件签署。实际车主 customer_id 不变，技术应用账号不写入被授权人字段。

## 两项独立事实

1. 业务授权文件：自行生成 PDF、上传法大大、车主本人手动签署、可信查询验证并下载归档，记为 SIGNED。
2. 渠道自动签权限：现有官方文档只明确 before_authsign 自动生成授权函能授予该权限，未确认任意普通 PDF 签署能替代。单方文件 SIGNED 不转换为渠道 AUTHORIZED，不允许因此启用自动盖章。当前三个执行开关保持关闭。

## 存储与迁移

OwnerAutoAuthority 增加 method，缺省 PROVIDER_AUTO_GRANT，旧两条 UNKNOWN 记录保持原有类型、编号及证据。新 UNILATERAL_LETTER 记录关联一条 OwnerAuthorizationLetter，保存批准模板 id/version/hash、正文、车主/法人/证书/印章快照、源 PDF 哈希、印章坐标、上传和签署状态、签后文件及查询证据摘要。新文件使用全新 contract_id 和 transaction_id，幂等重入保留原编号。

业务授权书新增独立法律文档类型 owner-authorization-letter；配套 owner-auto-sign v3 说明区分文件签署与渠道权限。新模式要求两份已审定文案及完整同意记录，否则不开放入口。不覆盖已批准旧正文。

## 流程

法人确认三项范围与当前说明 -> 事务内核验法人关系、证书、印章及批准文本 -> 保存不可变文档快照 -> 渲染并校验 PDF -> 持久化上传意图并上传 -> 原车主企业的 extsign 手动签署链接 -> 查询完整主体/合同号/交易号 -> 下载签后 PDF -> 归档并显示“授权书已签署，自动用印尚未开放”。

发起与重入均核验当前法人、企业、证书、印章和记录归属；未知上传结果只查询原合同，不重复上传。异步回调先验签再查询，不直接相信前端返回。源文件和签后文件只通过已登录的原法人及本企业权限读取，禁止裸文件路径或公开 URL。

新单方授权可以在本平台撤回/停用，保留原签署文档；不调用旧的账户级渠道撤销接口。已发出的签署链接撤回后不作为本地授权启用依据，晚到回调仍保留已签事实。页面不得称本地撤回为渠道签名作废。

## 本期门禁与验收

新模式 OWNER_AUTHORIZATION_METHOD=UNILATERAL_LETTER，仅支持 scope v2 和宁达固定名称。新授权入口独立受 OWNER_AUTHORIZATION_ENABLED 控制。新增文件已签不得进入旧自动用印状态机，即使误开全局开关也必须拒绝。

本地合成测试覆盖固定正文、车主为唯一签署方、不能改写被授权人、批准文本/同意/法人关系检查、幂等、上传未知结果、回调错配、下载失败、签后归档、未签不能启用、已签仍不能自动启用、旧记录兼容和安全文件访问。生产不自动签署、授权或盖章；正式文本批准前不发布新法律文案或恢复入口。
