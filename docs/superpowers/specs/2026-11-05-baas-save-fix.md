# BaaS登记保存验收修复

用户验收：当前合同可见、附件已上传，填完开始日期等资料后保存报“合同不存在”。从已部署baas-archive-v1冻结源隔离修复，不使用未发布root代码。

根因已由截图输入及真实service复现：承接原合同自由文本“无”作为previousContractId送入previous()，内部复用当前合同read()而产生误导404；保存事务回滚，日期等整次修改未持久化。只读线上确认当前记录存在、开始日期为空、有1份有效专用附件、无成功修改审计。

修复：承接改可选同车曾启用合同选择（业务编号显示、真实id传输、完整分页），明确“无承接”。不可读旧关系保持原值，未修改关联不增加保存门槛。兼容旧页面exact“无”/blank，在命令幂等校验之后规范为null；历史条款parser、16字段顺序及成功命令摘要保持原规则。无效承接用字段专属错误，真正当前合同不存在仍404。

详情区分已保存条款缺项、未保存编辑内容与当前有效附件；有有效专用PDF不要求重传。保存成功并回读后更新日期提示，不自动启用、不生成成本、不修改真实业务记录来代替用户保存。

用户补充的激活条件为八项：本车合法VIN、BaaS实际合同编号、与登记所有人一致的承租人、出租公司、起租日、月租价、每月支付日、代付人。实际编号优先使用supplierContractNumber；内部自动归档号不冒充实际合同号。新登记按月，旧季付/年付周期价格保留，不自动换算。电池规格、含税、宽限等为选填，不再阻断激活或商品发布。

代付人明确引用既有合作商VehicleOwner，新增payerOwnerId nullable无默认列及Restrict FK；不回填、不把登记候选变成租赁有效合作，也不额外要求合作协议已生效。目录推荐仅辅助选择，保存确认建立BaaS代付登记关系。激活与上架共享同一业务完整性校验；财务数学必需字段独立检查，原16字段解析、顺序、hash和旧成本历史不变。

必备材料为当前有效的签署后合同PDF，历史图片保留但不满足该条件。新BaaS上传仅PDF，其他资料类型不变。启用确认明确人工核对资料与签署PDF一致，审计冻结八项、PDF编号/摘要和操作者时间；不声称系统自动验证电子签章，不增加独立复核流程。

商品发布位置同时提供App展示预览和编辑资料入口，放在既有商品卡片内，包含车辆商品卡槽和商品中心。预览复用客户目录同一投影，草稿可授权预览但不伪造已可申请状态。编辑复用车辆共享标题、介绍、车况文字、照片/封面维护；明确同车商品共享，不篡改已发布产品版本的价格/条款，不自动发布。页面深度不增加独立详情层级，维持紧凑布局和未知命令、会话及版本保护。

真实隔离库发现旧 active_terms_complete CHECK 仍强制电池规格；在尚未发布的第75迁移中仅移除此项，保留五项财务必需字段、付款约束和单车一个ACTIVE约束，不改已发布的74个迁移。新迁移同时新增可空代付人引用，不回填历史数据。
