# 合作商运营办理与只读查看指引

更新：2026-10-28。版本：v2.2。

> **v2.2已发布，生产版本见[实施与发布记录](../evidence/ninda-partner-operations-v22.md)。** 本指引依据用户确认的[设计基线](../superpowers/specs/2026-10-28-partner-operations-readonly-design.md)和[开发计划](../superpowers/plans/2026-10-28-partner-operations-readonly.md)。以下步骤适用于v2.2后台；无需合作商注册客户小程序，也不能补造账户、授权或审批数据。

旧指引已[原文归档为 v2.1](history/ninda-partner-onboarding-guide-20261028-v2.1.md)，仅用于识别当前实现和历史操作，不再作为新合作流程的操作指令。文档更新不证明任何主体已授权、材料已核对、合作已生效或款项已支付。

## 先分清三类人员

| 对象 | 来源与用途 | 权限边界 |
| --- | --- | --- |
| 宁达运营经办、复核人员 | 内部员工账户；录入、核算、登记实付与复核 | 获授对应权限的不同实际人员独立办理，不以换账号代替分权 |
| 合作联系人、签署人或授权代表 | 依据真实纸质材料登记主体、签署及出租合作范围 | 属于业务资料，不自动获得登录、签章或其他系统权限 |
| 合作商只读管理员 | 运营登记手机号及查看范围，独立复核启用 | 本人验证手机号后从服务号查看；不是后台 ADMIN，也不自动成为签署人、收款人 |

合作依据是线下协议。没有客户小程序账户、没有查看手机号、从未登录 H5，都不应阻止运营准备和办理具备真实依据的合作材料。平台运营也无需先注册客户小程序。

## 开始前：由管理员配置内部人员

进入**系统设置 → 人员管理 → 人员详情 → 合作业务能力与实际人员归属**。先核实账号的实际使用人：新人员建立稳定标识，同一人已有其他账号时选同一人员。已有归属不可改写，不能用新标识规避自审。

按职责点击“配置合作业务能力”，分别配置合作资料、查看授权、规则、收款账户、结算、实付的读取、经办和复核权限。经办人准备资料，另一名实际人员复核。权限变更会使该账号旧会话失效，需要重新登录；ADMIN和历史FINANCE账号也不会自动获得全部合作权限。

仅登记查看手机号时，经办账号至少需要“合作资料与档案 → 读取资料”和“手机号查看授权 → 读取资料、经办及提交”。复核账号需要对应读取权限及“手机号查看授权 → 独立复核”，并核实实际人员归属。未配置权限时，合作商档案页显示配置指引；旧 `#vehicle-owners` 链接仅提示进入新办理入口。

初次升级后相关菜单不可见时，先完成上述配置；这不表示合作商需要注册客户小程序。只有一名实际办理人员时，可以准备草稿，不能用两个账号替代双人复核。

## 一、运营录入合作资料

目标路径为：**建立合作商 → 录入真实线下协议及附件 → 关联车辆 → 录入分润约定 → 提交合作资料复核 → 另一位运营复核**。

1. 建立企业或个人主体，依据材料填写真实名称、主体信息、联系人及签署代表；缺项先保存草稿。个人合作商不要求企业信用代码。
2. 录入协议的真实签署情况、合作车辆、起止日期及附件。已线下签署的协议直接登记并上传完整原件，无需为了录入系统重新生成或重签；尚未签署时保留待办，不把上传附件当作签署完成。
3. 核对车辆出租或合作权限，按实际证据关联车辆。车辆已上架、营业执照已上传或手机号相同，都不代替权属和签署授权依据。
4. 按真实约定填写分润条款；未知项保持待补并列明缺项。无需选择客户账户或“已核验身份关系”；必要的主体、代表及车辆权限核对纳入合作资料复核。
5. 另一位有对应复核权限的实际运营人员核对主体、车辆、期限、条款、签字盖章及完整原件。经办、提交和材料上传人员不得审核自己的同一事项；ADMIN 参与业务也不例外。

目标办理页集中展示各领域资料、退回原因和下一步。部分步骤成功不表示整套已通过；同一操作网络重试沿用原幂等键，版本变化先读取最新记录再核对，已归档历史版本不可原位覆盖。

## 二、合作就绪与日期、金额

“合作资料已复核”不等于本车现在可以下单。新订单仍须有有效主体资料、明确车辆关系、覆盖车辆及完整拟租期的已归档协议和已核准规则，同时满足车辆和产品可售条件。未开通或停用只读账号不影响这些合作事实。

首批三家合作期为 **2026-10-28 至 2031-10-27，含起止日**。该期间不自动用作查看授权期、分润规则有效期或客户逐单租期；各自按真实约定核对。

平台月租服务费比例保留 **20%**，**计提基础继续留空，待双方确认**。可以保存待补草稿；不能擅自按应收、实收或扣除退款后金额计算，不用“待定”占位形成生效规则或虚假应付。新订单所需最终规则须有明确依据及有效期。

收款账户不是客户申请前置；编制人工结算前才须核对并独立复核正确账户版本。保单保障、订单资金、客户查验和交接继续执行原门禁，不用旧保单、假到账或虚假确认解除阻断。

## 三、可选开通只读手机号

查看授权独立于合作准入、纸签生效及业务核对。

1. 运营进入“合作商管理 → 合作商档案 → 详情”，在“手机号只读查看授权”点击“登记或更换查看手机号”，登记当前主要查看手机号及本合作商范围；未填可保持“查看账号未开通”。首版每家一个主要号码，同号码可逐家授权，不自动扩散权限。
2. 新增或改号先保存为候选号码，候选不赋予任何读取权限；另一位有查看授权复核权限的运营确认后才启用或替换当前授权。复核前当前授权按原状态有效；如需立即停止旧号，单独办理紧急停用。保存号码不自动发送邀请短信，不要求对方先注册客户小程序。
3. 对方从服务号“合作商中心”进入 `/owner/`，用登记号码和短信验证码建立独立只读会话。菜单及真实手机登录在实施发布时验证，本指引不声称已完成。
4. 改号或变更范围在独立复核后生效替换时，立即撤销旧会话的相应范围及旧验证码；候选保存不提前赋权。紧急停用由有权限运营立即办理，重新启用须复核。撤销某家不影响其他独立授权，改回原号也不能复活旧验证码。

只读查看手机号及账号状态独立维护，其变更不应使协议、车辆绑定、分润及已成立订单失效。普通联系信息仅在不参与合同、出租方告知或其业务快照时属于无合同影响字段；已经写入这些文书的联系方式变化须按文书影响生成新版本并复核，不倒改历史。主体法定资料或合作条款实质变化同样按受影响范围更正，既有订单保留原快照。

## 四、合作商端只看，不办理业务

目标页面为“合作概览／车辆／订单／分润结算”，只读取获授权主体的已发布资料、必要订单信息、保障摘要、协议文件和已复核结算及实付状态。

不提供编辑、上传补件、认领、确认协议、审批、反馈留言、签署或同步、修改收款账户、付款登记、提现等业务动作；服务端同样拒绝旧链接和旧会话的业务写入。发送验证码、登录、退出属于认证动作，不代表业务办理。

草稿、待复核金额、内部备注、完整收款账号、客户证件和风控资料不向外部展示。管理员手机号授权不替代客户逐单向实际出租方提供必要资料的同意；文件下载逐份核对主体和数据范围。

有疑问时电话或线下联系运营，由运营登记争议及处理结果。关闭 H5 反馈入口不自动关闭历史未解决反馈，也不解除原资金及履约暂停条件。

## 五、运营统一核算、付款登记与复核

获授相应权限的运营办理规则、收款账户、结算编制及实际付款登记，另一位有复核权限的实际人员独立核对。FINANCE 不再是新合作流程必须另设的岗位；旧财务账号和历史操作保留，权限由管理员明确配置，不自动扩权。

系统汇总真实订单收款、退款和已使用来源，运营依协议人工核算并提交，金额以整数分保存。押金不作为租金收入；退款、负调整、重复来源、冻结规则及账户版本均须核对。完整收款账户和凭证只供相应运营财务权限人员读取。

线下真实付款完成后登记实际日期、金额和凭证，再经独立核对标为已付。登记不触发银行转账；不得以手工勾选、假凭证或前端成功提示代替实际付款。客户支付、退款、异常到账继续走专用权限和原渠道事实校验，不因合作商流程调整而放宽。

## 六、实施前后衔接

实施前可收集真实主体、车辆、协议及条款材料，但不得虚构客户、审批或修改数据库绕过现网限制。正式办理以共同通过验收的后台、API、H5 和最新发布记录为准。

迁移保留原合作商、车辆、订单、文件及账本 ID、原签署及审核人、已付款快照和未解决争议。旧身份绑定不自动变成新只读授权，解除客户依赖也不自动批准合作。历史 ESIGN 按原模式和凭据保留；改号只改变当前读取权限，不追溯修改谁曾签署、审核或收款。

代码与发布验收已完成；本指引不证明具体员工已获授权、合作材料已审核、查看号码已启用或实际付款已发生。真实事项仍按对应记录和独立复核结果办理。
