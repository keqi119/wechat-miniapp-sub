# 试运行合同与取消办理指引

2026年10月30日。本版流程已上线，版本`20261030-contract-trial-v1`，见[发布核验记录](../evidence/ninda-contract-trial-flow-20261030.md)。覆盖旧指引中协议双人复核、保管人/位置必填和取消准备并行办理的描述；身份、保险、真实退款审批等业务权限不因此改变。

## 合同如何办理

1. 在合同模板中选择完整草稿，核对正文后“启用此版本”。新档案只能选已启用模板；已建档案保持原模板，旧版停用不改变原签文件。
2. 在订单的合同步骤建立所需档案，确认合同编号并生成。本单价格、期限、里程、主体等从已确认快照读取。
3. 打开PDF核对并打印，点击确认。重新生成或改变正文来源后需要重新确认。
4. 线下真实签字后上传完整文件，填写签署日期和页数，核对文件顺序；提交并审核。具备权限的同一运营可办理，不需要另一个账号，不登记保管策略。审核仍须真实核对签署方、签字页、清晰度、主体和商业条款。
5. 审核通过显示“待归档”，明确归档后才放行依赖合同的下一步。原文件、版本和操作记录保留。

页面只展开当前步骤，后续步骤按前序完成情况解锁；已完成步骤可回看。发现错误时新建补正版本，不能改写旧签字版。历史或失效版中的未处理反馈也可在反馈区办理，反馈处理不等于修改历史合同。

没有上传签字材料的草稿，可返回预览步骤修改并重新生成；已有签字原件的草稿须建立补正版本，旧版显示“已被修订版替代”并保留材料，新版重新生成和签署上传。草稿也可通过“更换模板并建立新版”选用新启用模板，现有档案不会自动升级。已提交版本须先退回再补正；待归档版本可直接建立补正。

## 终止协议如何填写

终止协议只引用该单实际已签主合同的名称、编号及原冻结的相关条款。生成前填写终止原因、生效时间、车况查验/交回安排、违章状态、结算依据、应补款、应退款、必要保留押金及未决事项。

金额必须明确填写，包括没有款项时填0；不自动推算提前解约补偿。非零应补或应退款须填相应日期；保留款和待处理违章须有具体安排与期限。系统的收退款汇总是核对参考，不代表各方已同意的结算结果。

未交付明确不需要还车查验；已交付未收车填写计划时间地点，不能写成已还车；已收车采用真实接收记录。证据矛盾或缺少原合同资料时先核实，再生成。新模板不追溯替换老订单原约定。

生成时的原合同、VIN和交接依据单独冻结，与当前资料分开展示；变化后按提示重新生成或补正。后续真实退款成功不会改变已生成原文。若原合同已有生效补充协议，本版阻断自动生成，不自动合并或用主合同旧条款覆盖它，也不提供人工勾选直接放行；此类情况需补充支持相应条款核对的流程后才能继续。

历史已提交的终止协议如果缺少上述来源快照，须先退回，再建立补正版本重新生成、签署和上传。历史租赁档案不会因此被追溯改写。

## 交付前取消如何办理

从订单取消分支，依次完成“确认签署情况 → 必要终止协议 → 资金核查 → 确认取消”。已审核/归档的租赁签字版可直接证明已签；没有既有事实时，由运营核实登记实际情况及原因，附件选填。不能把已签改报未签以跳过终止协议。

未签可跳过终止协议；已签须终止协议真正归档。资金核查按账单、收款、退款表格展示，点金额进入具体记录，可返回本单。收款详情可申请绑定该笔原支付的退款；退款仍按原权限审批和渠道结果办理，审批或提交不代表退款成功。未支付款不要求先付款再取消。

所有当前条件满足后才能确认取消。已交付订单走真实还车与结算，不使用交付前取消跳过交回。查看页面不会自动取消、退款或终止合同。

## 文本版本

订阅合同和终止协议v2已于2026-10-30经用户审定并正式启用，见[正式文本及版本记录](../legal/versions/ninda/offline-mvp-v2/README.md)。新建档案可选择v2；原已建档案不自动改版，需要采用新文本的未签草稿选择“更换模板并建立新版”。模板启用接口修复版本为`20261030-template-lock-v1`，页面和其他流程保持原样。
