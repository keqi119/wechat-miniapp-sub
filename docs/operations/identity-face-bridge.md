# 小程序实名刷脸衔接

适用个人实名与企业经办人实名。`MINIAPP_FACE_BRIDGE_ENABLED` 默认关闭；只在原生签约开关、现有生产法大大账号及两项业务域名均就绪时公布 `FADADA_H5_CURRENT_FLOW_V1` 能力。合同或自动签署中的刷脸不在本次入口范围内。

沿用法大大官方 5.1.2 中间页流程。供应商当前移动端脚本在用户主动请求刷脸后，从 `generateFaceUrl.action` 响应取得 `bizToken`、`miniProgramAppId`、`miniProgramPath`、`miniProgramCallBackUrl`，编码后进入本小程序中间页。目标小程序是该响应动态提供的，不把文档未承诺的 AppID 猜成静态配置。

中间页必须位于当前已加载的 `pages/sign/index` 后方，并与内存中的服务器原始认证链接、业务编号、客户会话、流程代次及有效期相符。外部直接打开中间页、其他业务页或旧会话均不能取得跳转能力。只接受有效小程序 AppID、无查询参数的页面路径，以及 `realnameverify.fadada.com` 或已登记的 `realnameverify16.fadada.com` 下 `/fddAuthenticationService/` 回调；通用实名域名映射到已登记域名，保留不透明查询及路由片段。四项参数由已加载的可信供应商页面提供，而非新的公共配置或认证成功证据。

用户需再次点击中间页按钮，微信确认后进入供应商认证小程序。只有已发起且实际离开过中间页、返回场景为 1038、来源 AppID 与本次目标一致时，才消耗一次性内存凭据，将原认证页重载到本次回调。`faceResult` 不改变认证、证书、企业成员或合同状态；后续仍走原服务端可信查询。

令牌和回调只留在当前进程内存，不写应用存储、日志或公开证据。退出登录、换用户、旧流程替换、任务失效均拒绝旧凭据。普通取消不重新调用企业注册或创建认证交易；返回原企业入口可复用已经保存的认证链接。

验证分别记录为：自动化流程测试、微信开发者工具编译与界面检查、本人真机刷脸及服务端认证结果。前两项不代替最后一项。
