# 企业车主签约发布与验收

本版沿用现有法大大应用。车辆出租方使用自己经过核验的企业身份、证书和印章；晓浪负责平台接入及交接作业。旧技术验收文件保留原通道。

## 发布次序

1. 验证独立生产数据库备份可恢复，应用 021–023 迁移，发布 API 与后台；三个 OWNER 开关初始均关闭。
2. 发布已获用户批准的六份车主文本及三份后续模板，核对公开接口的版本与内容摘要。
3. 根据已确认资料建立企业草稿，生成仅指定手机号可接受的邀请。开启 `OWNER_ONBOARDING_ENABLED`，由经办人本人完成认证，查询证书并核对选用印章。
4. 核验车辆归属凭据、租赁条件及客户逐单资料提供同意后准备合同，运营核对完整 PDF。开放合同能力前核对实际验收范围。
5. 经办人逐份手动签署；双方可信查询及签后 PDF 归档齐备后才推进订单。自动签署另需渠道授权、明确车辆/模板/期限/金额范围及本人主动开启，不能由运营代开。

## 异常处理

- 企业认证或文件上传结果未知时保留原请求，查询原交易；不得重复注册、重新用印以试错。
- 撤销任一历史授权会先关闭企业账号的全部本地授权；已发出交易继续核验，不推定撤销已完成。
- 更换印章或证书后，仅未上传、双方无签署尝试且无处理中请求的准备文件可重新绑定。系统轮换任务编号并清除运营复核，保留文件和审计映射。其余状态必须核验原交易。
- 小程序 PDF 阅读记录只在同一会话、企业、任务及文件摘要下保留。返回后签署同意重新由本人选择。

## 完成标准

自动化测试、页面预览与部署成功分别记录，不替代真实企业认证、实际合同签署或微信正式发布结果。实际逐单条件、车辆保险适用性、支付能力和交还事实按原订单验收计划逐项确认。

已知界面不足：客户端合同列表仍显示汇总签署进度；企业经办页面可查看两方状态。后续补充客户侧分角色展示。

## 企业认证入口修正（2026-10-17）

真机反馈的“结果尚未核实”源于签署页未解码路由参数：企业组合编号中的冒号成为 `%3A`，导致本地认证链接查找及状态查询失败。现在进入页面时先解码，异常编码拒绝进入；实名认证、自动授权、撤销授权及合同签署四类企业入口均已覆盖回归测试。邀请码改为两行文本框，普通输入框也明确设置高度。

微信开发者工具已验证实际参数解码和 43 位合成邀请码显示。生产只读核对显示原邀请已接受、原认证交易和链接已存在，企业仍待认证；用户可从原企业继续办理。此次不修改 API 或数据库，也不重新创建企业身份或认证交易。真实办理结果仍由本人完成后核验。
