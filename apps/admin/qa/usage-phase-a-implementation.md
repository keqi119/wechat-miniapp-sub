# 第二阶段A：月里程、里程包与退订结算后台

2026-10-16，范围仅`apps/admin`。按API实现人员定稿DTO与实际控制器对齐，未新增根依赖、修改API/部署或提交。

新增月里程台账与退订结算管理资源，复用筛选、分页、只读详情和明确动作。财务/ADMIN同时具备对应write权限、服务端canSettle/canResolve/canComplete为true且业务状态匹配才显示结算动作；运营可在canRequestEvidence为true且READY/REVIEW_PENDING时，填写理由要求重报证据。动作分别校验角色，客服只读。结算提交只含当前revision和稳定idempotencyKey，人工解除争议额外提交resolutionNote，无费用/余额输入。未知状态/能力缺失默认隐藏。写后重新读取当前资源与订单usage-account；月读数审核还重新读取关联period。

订单、月台账、退订与里程申报详情显示独立usage-account：真实起算/归还日期、每期基础额度、超额单价、到账包及剩余、产品快照、消费/失效流水、已发布购买文案和退订关联。月界readingId链接仪表照片与审核，退订关联月份/账单可直接跳转。未结算的默认0值显示“待核算”，不把它当最终零费用。没有手工标已付、加余额、代客购买或代客户争议动作。

月界读数APPROVED额外要求默认不勾选的boundaryConfirmed，明确照片为本月界或归还日且无跨月推算；拒绝入口表述为退回补证。旧无periodId读数不发送该字段。交接create/revise新增必填actualAt，显式上海时间转ISO，不依赖浏览器本地时区。正式方案至少12个月，1500公里/150分每公里固定只读并照契约发送，usagePolicy及应退押金只读展示。MILEAGE_EXCESS草稿归入已有不同财务复核门控，创建人不能自审，也不能未复核直接发布；零费用不造账单。

法律类型支持mileage-pack/usage-policy草稿，但不生成文案或自动发布。purchaseTerms缺失时准确显示暂不可购买，历史读取保留。里程包只抵当前未结算用量，已结月不追溯，余包本订阅期结转；退订先冻结待历史月结清，未用余额失效且不退费。没有扩展换车B阶段。
