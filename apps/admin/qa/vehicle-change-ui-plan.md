# B2 后台 UI 与测试方案（等待最终 DTO）

2026-10-16。范围仅 `apps/admin`；依据已批准 `apps/api/phase-b-design.md`、`qa/vehicle-change-design-review.md` 和正式换车文案。此时 `apps/api/b2-contract.md` 尚未发布，本文不声明新接口或字段，不写业务产品代码，不触碰已冻结 H5、API、迁移、数据库、生产或 Git 提交。主控已授权按最终 DTO 直接施工，无需重复商业审批。

## 页面安排

1. **订单详情入口与逐车概览**：读取服务端换车 context/账户；当前车辆取当前实际分配，nullable 明确显示“旧车已交还，换车待交付”。旧车快照不能冒充仍在使用。展示原期限、起租锚点、里程期不重置，及免费来源的周期、可用/预占/已完成扣次事实。可发起草案与否只认能力和阻断。
2. **独立换车列表/详情**：与 B1 延期区分类型过滤；不能将 VEHICLE_CHANGE 行误标“交车延期”。详情按“逐单报价→独立财务复核→客户确认→AMENDMENT 双人签章→资金门槛→旧侧交还→新侧交付→完成扣次”呈现服务端实际事实，不用线性进度条推断已完成。每一阶段能查看已有记录、缺项与原因。
3. **逐单报价表单**：目标车为真实可选库存，展示 hold 与当前车辆并存；预计交还/交付时刻明确北京时间。运营逐项输入协商结果，金额使用元输入/整数分发送；差价适用期、付款日、月费、押金沿用/补收/退款、交接费、计算依据、保险责任、停驶安排、取消与异常责任、报价有效期均按最终 DTO 填写。未批准项不自动填零/不适用，不偷偷按30天计算，不用负数表达退款。
4. **客户确认与不可变文档**：只读展示当前商业 hash、完整结构化资金安排和客户确认版本/时间；历史只展示 API 返回的真实摘要。未返回全文不假造。客户确认与签署由本人完成，后台仅准备 AMENDMENT 当前版本，跳既有双人复核页，不能走主合同 send。
5. **两侧交接事实**：旧侧/新侧各自展示车辆、分配、实际时间、同车仪表读数、照片证据、清单、客户响应、独立签署与完成状态。新建/修订 DTO 固定后才实现表单；不能以客户假异议解锁。旧侧已完成而新侧未完成时明确无车空窗、恢复当前 change，普通取消/新申请不能抹掉既成事实。
6. **免费次数账户与消费**：当前预占仅“预留”，不可标消费。显示服务端 source/cycle/hold/ledger、实际完成时刻和登记时刻；实际完成日期定所属免费周期，先免费后真实已购来源，后台晚点击不改归属。B3 购买不开放，不提供手工已支付、加次数、预扣或自动开单入口。
7. **月里程逐车分段**：订单用量卡/期间详情扩展服务端 segments，每段展示 assignment、车辆、起止端点及证据；分别核算/显示同车差值，再以服务端总用量和一次基础额度为准。缺任一段明确待补证；不跨车相减或取全车 max。已结期只读不覆盖。

## 模块与接入原则

- 新增独立换车 typed payload/能力/safe 投影模块与专用 UI；复用现有 Drawer、RecordForm、错误、金额、北京时间解析及 API Cookie/CSRF 客户端。无需新依赖。
- B1 只做必要 kind 过滤/导航适配，保持其已有测试与操作语义；不把 B2 typed 字段硬塞进 B1 表单。
- 运营与财务动作分离；ADMIN 也不能自己复核自己的报价。SUPPORT/FINANCE 文档正文脱敏按服务端返回范围，不以 UI 隐藏冒充服务端权限。
- safe `can*` 必须严格 `===true`，再检查后台角色和 resource permission；缺能力时隐藏写按钮但保留可展示的 blockers。资金显示只读真实到账/退款状态，不把报价当已付。
- 每次表单打开生成一次 key，同内容未知重试沿用；revision、hash 缺失拒绝发送。成功响应后回读 context/detail/账户与相关交接，不用本地余额加减或假完成。
- 处理中禁止跨记录写动作；用 abort/generation 避免旧响应覆盖新记录。网络未知保留表单，不生成新的签署/支付事实。

## 开工前必须固定的 API 事项（已发 API 同事）

- 列表 kind 筛选及 safe summary；context、detail、quote、finance、currentAssignment、swap-account 和历史白名单。
- quoted typed 资金行/期间/阶段条件/取消责任，以及各动作请求 revision/hash/key 和返回形状。
- SWAP_RETURN/SWAP_DELIVERY 新建/修订路径及 DTO；是否沿用原 handover publish/sign/complete、这些动作权威能力来源。
- usage-account/period/mileage 的 assignment/segments/reading safe 字段及月界补证行为。
- 免费来源预占、跨周年重选、完成日期/登记日期、车辆空窗和目标 hold 的真实状态与 blockers。

接口未固定前不编造 canComplete、状态枚举、车辆查询参数或资金公式。

## TDD 与验证

先写有意义的红测试，再实现与最终 DTO 对齐的最小代码：

- 金额精度与方向：元→整数分，拒绝超两位小数/负数/空输入；零额是否允许只按 DTO，方向不能从负号推断。
- 必填 typed 资金/期间/责任与完整重复行检测；报价有效期默认空、必须未来，不加任意天数限制。
- can/role/resource/创建人复核守门；拒绝错 kind、缺 revision/hash、静默把预留标消费。
- safe 投影过滤供应商身份、旧门户身份及 API 未授权私有正文；空 currentAssignment 必须显示待交付，不能回退 order.vehicle。
- 两台车不同仪表基线、同月多个段、缺一段与 SETTLED：不在前端计算跨车差值/重复发基础额度。
- 费用/签署/车辆/次数守门冲突及未知状态按原服务端错误展示；稳定 key 重试、失败不生成“已完成”。

隔离 Chrome fixtures 覆盖 ADMIN/OPERATIONS/FINANCE/SUPPORT、真实空态和离线、当前车辆空窗、hold 冲突、免费预占未扣/完成才扣、跨周年实际日期与登记日期分开、三种 AMENDMENT 准备阶段、两侧事实待确认/已签/只完成旧侧、缺里程段阻结算、私有正文缺失、表单保留与慢响应跨记录。全部 API 拦截，不访问生产/数据库/供应商，不伪装真实端到端成功。

最后运行本包相关单元、必要现有 B1/A 回归、TypeScript/Vite、390px 浏览器布局和页面错误核验，记录最终结果及明确未验证边界。根负责共享依赖与外部系统真实验证。
