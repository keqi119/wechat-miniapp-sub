# B3 原生客户端独立只读审查

2026-10-16；范围为主工作区 `apps/miniprogram` 当前 B3 修改。没有改客户端、连接数据库或调用真实渠道。

核对 `src/services/paid-swap.js`、`src/services/swap.js`、`src/services/api.js`、`src/pages/records/index.js/.wxml` 及付费次数测试。未发现尚未解决的 P1/P2 阻断。

- 创建只接受当前服务端固定产品及专门同意快照；刷新账户后核对文案标识、版本、hash。默认不勾选，创建仅产生原普通账单，未自动调用微信支付或本地发次数。
- 客户、令牌、generation 在异步边界核对；稳定请求键涵盖客户、订单及专门同意版本。清会话使旧响应失效，旧 finally 不释放新操作租约。
- 查询沿原 paymentId；失败或未知保留原来源，不另起付款。关闭前重新读服务端能力，已可信 VOID 直接回读原记录，不二次 POST。
- ACTIVE 必须原信用来源存在且账单可信实收 80000 分；预占单独显示不可另用。PAYMENT_REVIEW、REFUND_PENDING、退款失败/拒绝与实际到账分开，不以单次退款失败推定已恢复。
- 购买/流水使用白名单，无供应商原文、OpenID 或支付参数展示。nullable changeId 不构造假换车链接；购买流水时间已改为“实际发生”。RESTORE 只读。

交叉审查同时发现后台公共 ApiClient 的旧 401 清除新会话问题，已在后台以三个 Promise 交错回归先红后绿修复；不是客户端遗留问题。客户端作者报告 23 专项通过及离线截图；这些证据不代表真实供应商付款成功。本轮真实本地 HTTP 验收另行记录。
