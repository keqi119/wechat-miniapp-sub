# 阶段 B 最小 API、数据方案与实施切片

2026-10-16。设计提案，供主控审批；本轮仅新增本文，不修改已冻结 A 产品源码、迁移、数据库或生产配置。依据后台只读审查 `apps/admin/qa/vehicle-change-design-review.md`、已批准 `usage-policy-v1` / `vehicle-change-v1` 及本轮两项用户确认。

## 已确定的业务边界

1. 延期交车保持原订阅月数，起租日、结束日与月账单周期整体移动至双方确认的实际交车日。延期费用、补偿、已收款安排逐单协商并签补充协议。不能在交付完成时静默改日期。
2. 换车不重新起算原剩余期限或里程月，不重发当月 1,500 公里。逐次报价明确车辆、月费、差价、适用期、交接费用及必要责任说明，客户确认并签署。
3. 先用实际完成时所属 12 个月周期的免费次数，再用已付费次数。申请、报价阶段只预留，不消费。免费周期锚点沿订单真实起租日、原日号周年算法，未用不结转；购买次数限本订单订阅期。
4. 实际完成时间取已经双方确认的物理事件：旧车交还与新车交付均完成时的时间，顺序交接时即新车实际交付时间。后台晚点击“完成”、签署回调晚到、申请日期均不能改变所属周期。同时记录 `actualCompletedAt` 与 `recordedAt`。
5. 不自动扣押金，不以负数支付代替退款，不改原 `finalPlanSnapshot` / 主合同 PDF / 已付支付请求 / 已结月份。当前车辆指针可以在合格换车完成事务中变化，但它只是分配台账的投影，不是换车事实本身。

后台稿第 7 节的 12 组问题无需全部作为前置询问。第 1、2、9、10 组的全局关键口径已由上述确认覆盖；具体金额、当期分摊、交接费、押金补退、停驶安排、报价有效期、各阶段取消与违约处置，都可以由每次报价列明并获客户确认。没有这些逐单必填资料时阻止发出该报价，不能替运营填零或假设不退费。B 阶段当前没有另一项必须先问用户才能设计数据结构的全局选择。

## 推荐结构与不采用的捷径

推荐保留订单，追加不可变变更版本、资金调整计划、车辆分配段和次数账本。延期和换车共用确认/签署基础设施，但具有不同生效守门。直接覆盖订单快照会破坏已签文本；退订重建订单会重置期限、免费周期和已购里程余额，均不采用。

最小实现不建设自动差价引擎：运营给出整数分的结果及明确计算依据，财务复核分项合计与资金安排，客户看到同一结构化清单。将来如引入日费算法，再增加带版本的计算器，不从自由文字偷偷执行公式。

## 数据增量

以下是职责级模型，最终 Prisma 名称可在 B 施工 brief 固化；不预占下一迁移号，避免与 A 发布修复冲突。

| 模型/字段 | 最小内容及约束 |
| --- | --- |
| `Order.revision` / `effectiveTermsVersionId` / `currentAssignmentId` | 订单级序列化入口，交车前没有 UsageAccount 也能锁；有效条款指针只指已生效版本。原快照不改。当前分配可为空，明确表示换车待交付，不以旧vehicleId冒充仍可用车。 |
| `OrderChange` | order/customer，kind `DELIVERY_DELAY` / `VEHICLE_CHANGE`，业务状态、当前报价版本、原主合同ID、变更前有效条款hash、目标车hold、两侧交接ID、actualCompletedAt、生效ID。每订单最多一个非终态变更（部分唯一索引）。 |
| `OrderChangeQuote` | 追加的 revision、原/新日期及月费/押金、目标车辆身份及保险责任、逐项费用与适用期、结算与取消安排、期限、legal完整快照、commercialHash、客户确认版本/时间。报价发布后不可改；修订追加版本。 |
| `OrderTermsVersion` | 由原快照及已签补充协议派生的完整有效运营条款、previousVersionId、effectiveAt、原/新值、不可变hash。延期变更日期；换车保持结束日、原月界和包账户。 |
| `Contract.kind=AMENDMENT` / `changeQuoteId` | 复用合同归档字段但独立业务种类与一对一报价关系；源文档/签后文件/供应商任务/租约齐备。补充协议 SIGNED 不能触发 `advanceToHandover` 主合同逻辑。 |
| `ChangeFinancialPlan` + `ChangeFinancialLine` | 绑定quoteHash，行方向 `CHARGE` / `REFUND` / `REALLOCATE`，正整数分、原因、期间、原Bill/Payment、目标服务期、对应新Bill/Refund、财务请求/复核人、状态。不可把方向编码成负金额。重分配不制造新到账。 |
| `OrderServiceObligation` + `PaymentAllocation` | 当前服务期的日期、到期日、应付额、条款版本，引用真实原Bill及实际成功支付。付款沿用原交易，已收款改服务期通过追加释放/分配记录，净分配不得超过实付减已退金额，不能跨客户/订单。未付旧账单安全作废后新建替代账单，旧账单不覆盖。 |
| `VehicleReservation` | 独立目标车hold，vehicle/order/change/quote/状态/有效期；每车最多一个有效hold。与现有 `reservedOrderId` 当前占用统一通过车辆锁检查，不能用伪orderId绕过该字段的唯一约束。 |
| `VehicleAssignment` | 真实order/vehicle、交付/交还actualAt、同车起止仪表、交接ID、变更ID。旧段关闭后不可重写；同车有效分配唯一，同订单同时只有一个实际用车分配。 |
| `Handover.assignmentId/vehicleId/changeId` | 新语义 `SWAP_RETURN` / `SWAP_DELIVERY`，与最初DELIVERY及最终RETURN区分；按change+side约束当前交接版本，而不是整个订单type只能一次。manifest含车辆、分配、actualAt、读数、证据。 |
| `UsageSegment` / `Mileage.assignmentId` | period+assignment，端点来源/实际时刻/同车读数、关联照片、版本。月结冻结全部段与证据hash，SUM各段差值后只用一次基础及包。不再拿不同车辆的仪表值相减或跨车取max。 |
| `SwapCreditCycle/Purchase/Reservation/Ledger` | 免费周期、已付购买、预占、完成消费、释放、失效、退款收回独立记录；来源分FREE/PAID，unique sourceKey保证只发/扣一次。完整未使用付费购买全额例外退款沿A冻结规则。 |

现有 `Bill @@unique([orderId,type,sequence])`、A退订按 `Bill.sequence` 判断未来月份、`deliveryReady` 只认首期Bill的假设必须一起收敛为“当前有效服务期义务及支付分配”查询。不能仅创建第二套 SUBSCRIPTION sequence=1，或用新sequence编号冒充第一个服务月。财务模型是必要窄适配，不推广成任意客户之间的钱包或抵扣平台。

## 逐单报价 DTO 的最小要求

共用 `{expectedOrderRevision, priorTermsHash, idempotencyKey}`。报价只接收真实已知数据；不接受客户端指定已签/已付/已生效或精确信用分。

- 延期：`newStartDate`、原月数（只读一致校验）、服务器推导的新结束日/月周期，逐期 `dueDate` 的协商安排、费用/补偿和原款分配清单、理由、交接安排。付款到期日期与服务期边界分别存，不能在后台默认同一天而隐藏变化。
- 换车：`targetVehicleId`、`plannedReturnAt` / `plannedDeliveryAt`、`newMonthlyFeeAmount`、差价适用起止期间、明确的 `calculationBasis`、已计算分项整数分金额、交接费用、押金变化及依据、保险/责任/停驶安排、取消和履约异常安排、报价截止时间。每项应收/应退/沿用款项都可回溯原账单与服务期间。
- 金额必需有typed字段；说明不能另写一套不一致金额。服务端校验总额、期间覆盖、不重复行、付款归属，财务双人复核后客户看完整版本。跨月变更必须逐期列明，不按固定30天自动分摊。
- 押金不因换车自动重算或重采信用。沿用金额、补收、退回均须该报价明确约定；若运营另要求新的信用核验，必须另走有效授权核验，不能复用旧申请授权去收新信用资料。
- 资金门槛写为明确的阶段条件。新补款默认不是自动扣款；客户须主动付。若逐单约定退款可在物理交接后办理，状态只能显示“车辆已换、资金尚待结清”，不可假称全业务完成；资金关闭动作仍守真实到账/退款。

## 最小接口建议

列表/详情均safe白名单，含版本、hash、当前可执行能力和具体阻断原因；不含OpenID、预付参数、供应商原文或身份证。客户路径只可本人操作；运营报价/交接，财务复核/资金核对，ADMIN仍不能自己复核。

| 方法/路径 | 请求或行为 |
| --- | --- |
| POST `/customer/orders/:id/vehicle-changes` | `{reason,idempotencyKey}` 真实申请；不在客户点击时预扣次数或自动占某车。 |
| POST `/admin/orders/:id/delivery-delay-changes` | 发起延期草案；无实际交车、无用量账户，订单无其它非终态change。 |
| GET `/customer/order-changes[/:id]` / `/admin/order-changes[/:id]` | 报价历史、资金计划、补充协议、目标hold、物理两侧状态、次数来源、当前条款。 |
| POST `/admin/order-changes/:id/quotes` | 新不可变报价版本，原订单revision+priorTermsHash守门，服务器生成quoteHash。 |
| POST `/admin/order-changes/:id/quotes/:revision/review` | 不同财务人员复核资金行；与普通Bill审核衔接，但不得用已审核资金行掩盖变化的报价hash。 |
| POST `/admin/order-changes/:id/publish` | 只公布完整、已复核、仍有效的这一报价hash。 |
| POST `/customer/order-changes/:id/confirm` | `{quoteRevision,commercialHash,idempotencyKey}`；绑定已读完整报价及法务版本，之后才能准备签署。 |
| POST `/customer/order-changes/:id/reject` | 说明理由；未实际履行版本可以拒绝，已签版本走明确终止流程。 |
| POST `/admin/order-changes/:id/prepare-signature` | 生成该版本补充协议PDF，进入现有双人签章审批；不自动代客签署。 |
| POST `/customer/order-changes/:id/sign` + `/sync` | 复用签署租约和可信query/回调，kind严格AMENDMENT，恢复原task。 |
| POST `/admin/order-changes/:id/handovers` | 仅换车，带side/assignment/actualAt/读数/证据。事实确认与单独签署复用Handover流程但不能落入退订路径。 |
| POST `/admin/order-changes/:id/complete` | 同变更ID幂等恢复；核对已签版本、车辆占用、资金门槛、两侧事实、当前周期额度，原子生效条款及次数消费。 |
| POST `/admin/order-changes/:id/cancel` | quoteHash+reason；能安全终止才释放hold/预占。签署/支付未知或任一物理侧已发生时拒绝普通cancel，进入可审计异常处理。 |
| GET `/customer/orders/:id/swap-account` | 当前免费周期、已付可用次数、预占/消费/失效/退款流水、购买说明、canPurchase/canRequest。 |
| POST `/customer/orders/:id/swap-purchases` | 固定80000分/次，数量有明确上限、说明doc/version/hash、accepted=true、key；创建真实Bill，可信支付才发放。 |

名称是待主控定稿的设计接口，前端不得在尚未定稿前据此上线调用。

## 时间、预留与并发的具体处理

- 免费周年按最初实际交车日锚定；换车不重设锚点。报价中的预计周期只是预览。完成时依 `actualCompletedAt` 解析周期，并且先当前周期FREE再PAID。跨周年时不能把上周期免费预占带入下一周期。
- 预占声明“最多消耗一次，免费优先；无免费时使用已明确持有并预留的付费次数”。如果实际完成时没有任何合法可用次数，交新车前就停在待处理，不自动开新购买或事后记负余额。若跨周期重新获得免费次数，则用新周期免费并释放付费预占。
- 实际完成日期与后台登记日期分开，晚登记需要已确认交接事实支撑；不能按服务器now换周期，也不能仅改预计日期回溯免费额度。已结束周期的历史消费仍按事件实际时间验证未重复，不覆盖历史失效流水。
- 最小B采取旧车交还后再交新车，允许同日连续交接；存在无车间隔时必须在该报价写清费用和责任。暂代车/双车同时占用不在此最小切片中，不隐式当成免费或无里程使用。如出现此实际需求，再给对应真实车辆分配和报价，不需要提前设计未知业务。
- 订单版本锁是所有变更、使用结算、退款、退订的第一把锁；随后车辆按ID排序锁，最后权益/分配。外部签署、支付调用绝不放在长事务内，使用现有lease/CAS及相同业务交易号恢复。未知供应商状态不能释放已确认车辆hold或重发新交易。
- 旧车物理归还后记录关闭分配并置UNPUBLISHED，当前分配为空、界面显示换车待交付，不因流程失败倒写“未归还”。所有服务/里程/交接的当前车辆查询改用有效分配，不从旧vehicleId继续受理新车用量。新车最后完成动作将其交付完成标记、新分配、有效条款、订单当前车辆投影及次数消费放入同一事务；此前已发生的旧侧交还独立保留。只有一侧完成时状态明确待处理，继续同change恢复，不能通过取消重新申请来重复获得免费次数。
- 任何影响已SETTLED月份的回溯换车拒绝普通录入；不改旧账。确需纠错以新异常复核/退款记录处理，先保证证据与客户协商，不能上线一个“强制完成”旁路。

## 建议实施切片与可验收界限

### B1：延期闭环

先做Order版本锁、不可变change/quote/terms、补充协议kind与独立签章策略、当前服务义务/真实资金分配、延期交付守门。已付第一期保留原Bill/Payment并经签署方案重分配服务期；未知付款先查原单，未付款旧单安全作废。实际交车日若再变化，继续阻止原版本交付，追加新报价/补充协议。没有生成合法生效版本前，A的延期409保持。

验收：保留月数与月底锚点、两次延期、已付不双收、未知支付阻断、补充协议错hash/错kind回调、双人复核、实际日再变化拒绝、同一完成请求恢复一次。B1可独立上线，不解锁换车。

### B2：逐车台账与免费次数换车

先补车辆分配/UsageSegment、hold与所有库存消费者的统一守门、免费周期账本/预占，再开放真实换车报价和两侧交接。不等付费购买上线才保证free-first和付费来源类型，但只有真实已有来源才能消费。月界照片按assignment提交，旧车闭段与新车起段不跨仪表比较；同一月份SUM段用量后一次扣1500及包。

验收：两个订单抢同一车、原车与目标hold并存、不同仪表基线、一个月两次换车、跨月界/月末/周年、缺任一段暂停结算、补证/结算/换车竞态、旧侧完成后恢复、完成一次扣一次、拒绝用A退订冻结整单账户、原期限与里程包余额不重置。每个完成事件按实际时间归周期，后台延迟执行不改变结果。

### B3：付费次数购买与例外退款

固定价产品、独立购买同意、真实Bill与可信支付GRANT、paid预占、免费优先消费、未用失效、完整未用购买的全额例外退款冻结。可复用A安全思路但使用专门次数账本；不把次数塞到通用Entitlement文本或里程表。

验收：重复支付回调、晚到支付/退订、预占与退款竞态、申请未完成不消费、跨周年先新免费再释放paid、无可用次数不能交新车、已消费或部分退款不得绕过专用复核。全部本地合成测试；真实付款与签署仍由主控另定明确范围。

B2/B3之间可保持购买入口关闭；已有免费次数足以完成B2验收。对外宣称完整B业务前，三个切片及异常恢复必须都验证。

## 主控审批时需要确认的工程范围

商业方向已明确，不再列一组重复用户问题。主控只需确认本稿的最小切片次序及工程边界：先B1、再B2分段+免费、最后B3付费；最小切片不支持双车重叠使用或任意部分权益退款。补充协议正式模板由主控以已批准规则起草批准，不由开发生成未经审定的默认责任条款。B实施前再确定最终DTO、迁移分工与测试库独占时段，A冻结文件此时仍保持不动。
