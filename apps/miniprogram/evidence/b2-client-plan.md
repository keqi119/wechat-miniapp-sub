# B2原生实施与测试计划

2026-10-16。依据已批准阶段B设计；本轮仅apps/miniprogram，原Mock及已冻结H5发布副本不动。API最终契约由apps/api/b2-contract.md固定，本文不把设计建议当已存在接口。

目标：客户真实申请免费次数换车，阅读当前逐项报价/确认期限和完整补充协议，保留原期限/月界/里程包账户，沿现有H5入口签署；两侧交接分别核对车辆、实际时刻和证据；每一车辆分配段分别提交本车月界仪表与照片。付费次数购买B3没有入口。

复用现有页面及视觉：用车页进入换车；权益记录页展示周期、可用/预占/消费及历史；orderchanges记录页兼容延期与换车独立详情，完整逐项报价默认未勾选已读；handover页允许按明确ID打开旧车交还或新车交付；mileage页按订阅月选择真实assignment/segment。H5签页不改供应商协议或回退外链。

实施顺序：

1. 接收并核对最终safe DTO，先写行为失败测试，避免猜字段或新建源码中不存在的能力。
2. 独立swap适配器：账户严格解析、申请前fresh canRequest、稳定幂等与busy、真实POST后只展示服务端结果；网络未知提示查询原记录，不自行假成功或自动扣次数。
3. 订单变更兼容VEHICLE_CHANGE：列表摘要、目标/原车、期内费用/押金变化/责任/期限全文展示；fresh revision/hash、当前批准文案及默认未勾选守门；补充签署仅本地H5指引，可信sync不自动生效。
4. 两侧交接按ID及manifest绑定车辆/assignment/actualAt，旧侧完成后保留事实、当前无车明示待交付；不能误显示退订结清或新车已完成。
5. 月度里程按assignment提交，服务端可提交能力和本车基线校验；不同车辆仪表不相减、不取max、不自行结算，只显示服务端分段/整月汇总。
6. 专项、全包、模板真实编译及actual-wcc离线截图，核对Mock哈希，报告冻结。无生产/DB/SDK/真实渠道/预览上传。

重点回归矩阵：

- 免费周期及次数完全按safe显示，预占不能当消费；可用为零、已有非终态申请、未知状态/非法数字不能申请；购买能力永不开放。
- 申请理由必填；POST返回真实记录、稳定幂等丢包重试、busy防重、401/403/409/429/5xx/网络错误不制造成功。
- VEHICLE_CHANGE与DELIVERY_DELAY精确区分，旧延期回归保持；不完整/含占位的正式正文、错误kind、旧revision/hash、过期未确认报价拒绝提交；已确认后的签署期限沿独立审批，不误用客户确认截止时间。
- 金额用整数分并按方向展示，原期限和订阅月界显示服务端值；月份结束日不含与订单最后服务日含明确区别，不能客户端推算收费。
- 两侧车辆、物理时间及证据不能混；指定旧侧/新侧ID刷新仍保持本记录，无有效实际时间不可确认；已确认历史可读，签署与实际完成分开。
- 不同车高低仪表基线分别显示与提交；同月多个segment、缺任一段、无当前assignment间隔、审核拒绝补证、已结月份不可编辑；照片日期按北京时间、提交绑定正确period+assignment。
- H5引导四类现有回归、普通账单付款/里程包/退订不退化；原Mock109文件两副本SHA不变。

尚待固定：swap-account字段/状态/周期边界；VEHICLE_CHANGE quote结构及正式文案类型；两侧handover/assignment标识；usage segments和readings路径/请求字段。最终契约到达后追加准确映射与执行结果。
